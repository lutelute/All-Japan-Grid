問題

公表資料は、
線形を教えてくれない

系統情報公表の様式や局所系統図から取れるのは、線名と両端の変電所だけ。 座標は端点しか無いので、機械は素直に直線（chord＝弦）を引いて満足する。

ところが同じ場所の OSM には、 本系統に繋がっていない断片が宙に浮いて実在している。 人の目には「根本的には繋がっている」と見えていた。

「細い線もあるかもしれないが、根本的には OSM の線で繋がっているように見える。 簡略化すると確かに直線に見えるが、ちゃんと線があるものにおいては地形的に線を辿ってほしい。 これは全部に言えること」

— オーナー観察（2026-08-16）

なぜ半年見落としたか

この欠陥は、指標に現れなかった

接続キャンペーンの評価軸は「孤立ノードが減ったか」＝連結性 KPI だった。 ところが 直線で繋いでも実線形で繋いでも、連結性は同じだけ改善する。

幾何の質は、連結性 KPI には一切現れない。 だから機械は「達成した」と報告し続け、誰も気づかなかった。

発見したのは人の目視だった（「遠い赤点」の距離監査に続き 2 度目）。 機械は論理接続を得た時点で満足し、物理線形の探索そのものを省いていた。

手法

EGGC の 4 ステップ

1
端点スナップ — コード端点を最寄りの OSM 頂点へ（≤ 2 km）。 基底モデルが更新されて頂点が動いても追従する
2
経路探索 — OSM 由来のエッジだけで頂点グラフを組み、Dijkstra で最短路。 合成エッジは除外し、kV 不適合にはペナルティ
3
証拠ゲート — 経路のうち宙に浮いた断片（off-main）が占める長さの比率が 閾値 0.7 以上のときだけ「その断片が公表線そのもの」と認める
4
スタブ置換 — 認めた場合のみコードを削除し、両端の取付スタブ 2 本に置換。 断片は次の連結性再計算で本系統に合流する
# 判定の中核（route_disclosure_edges.py） route, used = dijkstra(osm_graph, A, B) off = Σ len(e) for e in used if not e.main tot = Σ len(e) for e in used if route/chord > 2.0: # 迂回過大 keep_chord() elif off/tot < 0.7: # 他人の線 keep_chord() else: replace_with_stubs() # 断片＝公表線

「経路が見つかったか」ではなく「何で出来た経路か」で採否を決めるのが、 単なる最短路吸着との違い。

04 / 11パラメータ: stub_km 2.0 / max_ratio 2.0 / off_share_min 0.7
核心

なぜ「浮いていること」が
証拠になるのか

送電網は繋がっているので、経路はほぼ必ず見つかる。 見つかったこと自体は何の証拠にもならない。

off-main 比率 ≥ 0.7 → 断片＝公表線。置換する
off-main 比率 < 0.7 → 既設の別線を回っただけ。直線を保つ

浮いた断片＝「まだ誰も本系統に繋いでいない線」。 その区間にちょうど存在するなら、それがこの公表線である蓋然性が高い。 逆に経路が main の線ばかりなら、それは他人の線。

実測では採用 12 本すべてが比率 1.00（経路が 100 % 断片）、 棄却側は 30 本すべてが 0.00。 中間が存在しない＝この問題ではゲートが極端に効いている。

結果

90 本のうち、置き換えたのは 12 本

残り 78 本は直線のまま。うち 30 本は経路が別線の迂回、48 本はそもそも OSM に線が無い（地中線・未マッピング）。

直線を残すことも成果である。 直線は「論理接続は確かだが、線形は未収載」という正直な表現であって、 埋めるべき失敗ではない。無い線形を捏造しないことが、この手法の設計思想。

置換した 12 本ではブランチ長が直線近似から実線長になる （合計 160 → 197 km、+23 %）。PF / Ybus のインピーダンスが実長基準になる。

「吸着すると連結性が改善する」は誤解。 改善したのはデータの正しさであって、モデルの規模でも収束性でもない。

この手法が主張しないこと

  • off-main であることは「公表線である」ことの証明ではない — 「本系統に未接続の線が、ちょうどその区間に実在する」という状況証拠にすぎない
  • 閾値 0.7 に強い根拠は無い — 今回は 0.3〜1.0 のどこでも同じ答えになったので、 この閾値はまだ検証されていない。中間値が出る地域が現れたら再検討が要る
  • 棄却した 78 本が「正しく棄却された」保証も無い — OSM 未収載を確認したのであって、実線形が無いことを確認したわけではない

位置づけ

この手法は何の仲間か

分野代表EGGC との関係
マップマッチングHMM マップマッチング（Newson & Krumm 2009） 軌跡（多点）→ 道路網への吸着。EGGC は入力が「端点 2 点＋論理接続」だけの退化ケース
地図コンフレーションSaalfeld (1988) 以来の map conflation 同一実体の 2 表現を統合する親概念。論理系統図 × OSM 物理図の統合が EGGC
経路推定path inference（疎な GPS 2 点間の経路復元） 2 点間の物理経路を推定する問題設定が同型
電力網 × OSMGridKit (2016) / SciGRID / osmTGmod / PyPSA-Eur いずれも OSM → トポロジ抽出（逆方向）。外部の論理トポロジ → OSM 幾何への写像は例が無い

新規性の主張点

  • 公表資料由来の論理エッジを入力とする（GridKit 系は OSM のみ）
  • off-main 比率という検証可能な採否基準で、吸着すべき断片と未収載を機械判別
  • 可逆な台帳駆動（累積マージ・regen 再現・BAK）

運用

取り消せるように作ってある

可逆性の 3 点セット

  • BAK — 正典適用の前に all.json.pre_route.bak を必ず作る
  • 台帳 — 採否の全記録を routed_disclosure_edges.json に。 置換 12 件だけでなく直線維持 78 件の理由も残す
  • 無効化 — regenerate_all.py の STEPS から外すだけ。 介入台帳 #29 追補 5 に登録済み

台帳は累積マージ。部分再実行が過去の記録を消すと、 apply 側の防波堤が守備範囲を失いコードが実線形の横に復活する（実害あり・対策済み）。

冪等であることの意味

適用後の正典で再実行すると、断片はすでに main なので 証拠ゲートはほとんど閉じる。同じ線が二重に置換されることはない。

この性質のため、教材とスライドの図は 適用前スナップショットを入力に再走させて作っている。 現行正典で走らせると「吸着 2 本」しか出ず、手法の姿が見えない。

regenerate_all の STEPS に組み込み済みで、 再生成のたびに自動適用される。

まとめ

線があるものは地形的に辿る。
無い線は、捏造しない。

EGGC は「繋げる」手法ではなく、「繋ぎ方を証拠で選ぶ」手法。 ゲートが開けば実線形へ、閉じれば直線のまま。
どちらも記録に残り、どちらも取り消せる。
