# 路線と鉄塔の層（docs/data/osm_routes）

系統図マップ（map.html）で、線を**路線ごと**に選び、**鉄塔**を出して選び、送電線・鉄塔・変電所・発電所・地名を**1 本の検索欄**で探すための層。2026-11-07 に作った（オーナーの依頼「鉄塔名とか線とかも選択できるように」）。

- **観測（OpenStreetMap）から作った derived の層で、正典（`docs/data/built`）とは別**。正典の枝・母線は変えない（docs/OBSERVED_VS_DERIVED.md）。
- 既定では出さない。線をクリックしたときに、その路線と鉄塔だけを出す。左の「OSM の線と鉄塔 → すべて出す」で全部出せる（2026-11-07 オーナー判断）。
- 地図データ © OpenStreetMap contributors（ODbL 1.0）。画面のカードにも書いている。

## 何ができるか

| | 操作 | 中身 |
|---|---|---|
| 路線を選ぶ | 地図の線をクリック | カードの「OSM の路線」に、その枝が通る路線（名前・電圧・区間数・長さ）を出し、路線の全体を光らせる。同じ路線に属する正典の枝も太くする。路線の名前を押すと路線のカードへ |
| 路線のカード | | 電圧・回線数・区間（架空・地中・海底・ケーブル）・両端（変電所・発電所・ほかの線へ・何もない所）・鉄塔の数・事業者・つなぎ方・Wikidata/Wikipedia・正典の枝の数・**同じ名前の別の区間**（つながっていない区間をまとめて光らせる）・OSM のタグと way の一覧 |
| 線の上の名前 | 路線を選ぶ | 選んだ路線の名前と電圧を線の上に出す |
| 地中・海底 | | 地中とケーブルは破線、海底は点線 |
| 鉄塔 | 路線を選んで寄る（ズーム 10 以上）／「すべて出す」で寄る（13 以上） | 番号（OSM の `ref`）・名前・載っている線（併架なら全部）・形・構造・高さ。「前の鉄塔へ・次の鉄塔へ」で線に沿って動ける。**番号の無い鉄塔に番号は付けない** |
| 横断検索 | 左上の検索欄 | 送電線（OSM の路線・正典の枝）・鉄塔・変電所・発電所を、表示中の電圧帯に関係なく探す。候補に種類と kV を出す。選ぶとそこへ飛んで選択し、カードを開く。「新長浜線 115」のように打つと鉄塔を探す。設備に無ければ Enter で地名（Nominatim） |
| 変電所の母線 | 変電所をクリック | 同じ敷地に電圧の違う母線があれば「（1）154 kV（2）66 kV」のように並べる（正典の変電所の一覧から） |
| 色分け | エリアのタブ | エリアごとと周波数（50/60 Hz）を切り替える |
| 共有 | URL | `map.html?route=地域番号.路線番号`・`?tower=地域番号.node id` で、選んだ路線・鉄塔を開く（`#` はタブの切り替えが使う） |

## 路線のまとめ方（src/topology/osm_routes.py）

OSM の送電線は細切れの way で描かれている（全国 35,605 本）。次の 3 つの規則だけでまとめ、どの規則でつないだかを路線ごとに数えて残す。

1. **同じ名前**：`name` を `;` `/` で分け、空白と末尾のローマ字の読み（「東海幹線 (Tōkai-kansen)」の括弧）を除いた組が全く同じで、電圧が食い違わず、点を共有する
2. **名前なしの続き**：名前の無い way どうしが端点で会い、その点に way が 2 本しかなく、電圧が同じ
3. **片方だけ名前**：2 と同じ条件で片方にだけ名前があり、電圧が分かっている（名前の無い側には隣の名前を当てる＝推定。カードに本数を出す）

つながないもの：

- **併架**（1 列の鉄塔に別の線が載る）。OSM では鉄塔の点を共有するが、電気的には別の線
- 電圧の食い違う way
- 名前の違う 2 つのまとまりを、名前の無い区間で橋渡しすること
- 「上群線/群馬幹線」のように 1 本の way に 2 つの線の名前があるもの（1 列の鉄塔に 2 路線）を介して、2 つの線を 1 つにすること

路線の番号は、まとまりの中で一番小さい way id（OSM が変わらない限り同じ番号）。

正典の枝の形（`built/all.json` の path）は、頂点の 98.3% が OSM の点と座標（小数 5 桁）で一致する。枝 → OSM の点 → way → 路線 は座標の一致だけで引いていて、推測は入れていない。同じ鉄塔を通る線が複数あるとき（併架）は、電圧の合う線を先に出す。

## 作り直し方

```bash
PYTHONPATH=. python scripts/export_osm_routes.py            # 既定で nas03 の 20261105 の抽出を読む
```

- 入力の鉄塔データは **git の外で、NAS に置く**（取得データは Mac に置かない決まり・2026-11-07）。nas03 の `PWS_DB/osm_jp_power/20261105_agj_transmission/json/tw_japan_t0.json`（Geofabrik の日本の抽出 2026-11-05 を `scripts/osm_pbf_to_power_json.py` で Overpass の JSON と同じ形にしたもの、51 MB、SHA256 は同じ場所の `MANIFEST.sha256`）。読む場所は `osm_routes.default_raw_dir()`: 環境変数 `AJG_OSM_RAW_TOWERS`（旧名 `AGJ_OSM_RAW_TOWERS`）→ `/mnt/nas03/…/json`（pws-160core）→ `/Volumes/PWS_DB/…/json`（Mac で nas03 をつないだとき）。Mac の `data/osm_raw_towers/`（6 月の Overpass の取得分）は読まない。CI では作り直せないので、出力（17 MB）を git に入れている
- 出力は、入力が同じなら毎回同じバイトになる（実行日は書かない）。`meta.json` に入力の SHA256・OSM の取得時刻・正典（`built/all.json`）の SHA256 を書く
- 正典を作り直したあとも、枝と路線の対応（`edge_routes.json`）は枝の始点・終点・頂点数を鍵にしているので、形の変わらない枝はそのまま引ける。形が変わった枝は「対応づけられない」と出るだけで、間違った路線は出さない。正典が大きく変わったら作り直す
- 規則の検査は `tests/test_osm_routes.py`、画面の検査は `tests/test_pages_map_ui.py`（路線・鉄塔・共有の URL・検索）

## ファイル

| ファイル | 中身 |
|---|---|
| `meta.json` | 入力・規則・数・列の説明・地域の範囲 |
| `routes_{地域}.json` | 路線（列の並びは `cols`。way の形は Google の polyline・小数 5 桁） |
| `towers_{地域}.json` | 鉄塔（列ごと。id・緯度・経度は 1 つ前との差。路線は `rl` への番号） |
| `edge_routes.json` | 地図の正典の線（始点・終点・頂点数）→ 路線 |
| `search.json` | 横断検索の一覧（路線・変電所・発電所） |
| `search_towers.json` | 横断検索の一覧（番号か名前のある鉄塔） |

参考にしたのは soudensen.com の「路線ごとに選ぶ・鉄塔を選ぶ・1 本の検索欄」という見せ方の考え方だけで、そのサイトのコード・データ・API は使っていない。

## 補完（2026-11-07 オーナー「鉄塔名などをちゃんと補完してほしい」「回線も省略されている可能性がある」）

OSM に無い値は、根拠のある推定だけで埋め、地図のカードでは必ず「推定」と書く（本物の番号・回線数に見せない）。Soudensen のデータは使わない。

| 何を | どう埋めるか | カードでの出し方 |
|---|---|---|
| 鉄塔の番号 | OSM の `ref`・`name` をそのまま。無い鉄塔は、同じ線の上で前後に番号のある鉄塔があり、間の基数が番号の差と合うときだけ埋める（12 と 15 の間に 2 基 → 13・14）。路線によって違う番号になる鉄塔（併架など）は埋めない | 「52（推定：前後の番号から・〇〇線）」、見出しは「No.52（推定）」 |
| 鉄塔の番号（端まで延ばす、2026-11-07） | 同じ線の並びに番号のある鉄塔が 2 基以上あり、どの 2 基のあいだも 1 基ごとに番号が 1 つずつ増える（減る）ときだけ、一番端の番号のある鉄塔から並びの端まで延ばす。1 より小さくはしない。前後から埋めた推定とぶつかる所・併架は延ばさない（`docs/reports/tower_number_extend_2026-11-07.md`） | 「35（推定：No.38 の鉄塔から 3 基先へ延ばした・〇〇線）」、「延ばした元の鉄塔（No.38）へ」のボタン |
| 番号の無い鉄塔の位置 | 路線が一筆書きにたどれるときだけ、北の端から鉄塔を数える | 「〇〇線 の 231 基目（全 253 基・北の端から数えた順。OSM に番号なし）」、見出しは「番号なし（〇〇線 231 基目）」 |
| 鉄塔の描かれていない所 | 架空線（power=line）の途中の点で鉄塔のタグが無いものを「線の折れ点」として、鉄塔とは別の印（中の空いた紫の四角）で出す。ズーム 11 以上 | 「鉄塔（推定：線の折れ点）」 |
| 回線数 | OSM の `circuits`。無い線は、交流は導体数 ÷ 3（3 の倍数のとき）、直流は導体数 ÷ 2、それも無ければその線を通る `route=power` の relation の数 | 「2 回線（推定：導体数 ÷ 3）」など |

- 取り直し（2026-11-07）: Geofabrik の日本の抽出（`japan-261105.osm.pbf`、OSM 2026-11-05）を pws-160core から nas03 の `PWS_DB/osm_jp_power/20261105_agj_transmission/` に取り、osmium で送電線・鉄塔・`route=power` に絞った（タグは全部）。`scripts/osm_pbf_to_power_json.py` が Overpass の JSON と同じ形に直す。Overpass で取る `scripts/fetch_osm_power.py`（地域ごとの 3×3）も残したが、1 区画に 1〜2 分かかり全国で 2 時間を超えるので使っていない
- 前と後の地域ごとの数、正典の回線数と OSM の回線数が食い違う線の一覧、公表値との一致率（集計だけ）は `scripts/report_osm_completion.py` が書く（`docs/reports/osm_completion_<日付>.md`）
- 公表の回線数（`data/reference/circuit_counts.jsonl`）は検証にだけ使い、出すのは一致率などの集計だけ
