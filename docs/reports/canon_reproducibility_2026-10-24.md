# 正典を clone だけで作り直せるようにする 2026-10-24

オーナー「この github 見た人が計算や生成を全て再現できるようにどんどん進める。まだ正典が弱い」（10-24）を受けた作業です。

## 結論

- **clone しただけ（git の外のデータが 0 本）の手元で `regenerate_all --light` を流すと、正典 `docs/data/built/all.json` がコミットとバイト一致します。**
  - `--light` で作る他の追跡ファイル（地図・SubSLD・単線結線図・変電所の属性・台帳）も一致します。
  - 違ってよいのは、実行の記録（`MODEL_VERSION.json`）と、#44 の報告（台帳から作ったと書く）だけです。
- CI のジョブ `reproduce-canon` が、push と PR のたびに同じことを確かめます。正典を変えるコードを直したのに正典を作り直していなければ、そこで落ちます。
- 手順は `docs/REPRODUCIBILITY.md` の冒頭にまとめました。

## 何が弱かったか（5 つ）

### 1. 正典に実行日が入っていた

- #44 の回線数の注記（`par_note`、336 本）と #34 第三波の `disclosure`（34 本）に、`date.today()` が入っていました。
- ノード衛生の台帳には実行時刻が入っていました。
- そのため、同じ日に 2 回流せばバイト一致しますが、別の日（別の人）が流すと一致しませんでした。10-21 の正典と 10-24 の再生成の違いは、この日付だけでした（注記の日付を除けば同じ）。
- 直し: 注記の日付は介入の採用日（どちらも 2026-09-02）に固定しました。台帳と構造 DB の集計には時刻を書きません。

### 2. 正典を作る手順が、git の外のファイルに頼っていた

再生成を 1 回流し、Python の audit hook で開いたファイルを全部記録しました（`trace_sitecustomize.py` と `classify_trace.py`、結果は `inputs.json`）。

- 手順の入力は、git で追跡しているもの 83 本と、git の外のもの 49 本でした。読もうとして無かったものは 0 本です。
- git の外の 49 本の内訳:

  - 足りなかったのは出典の種類（`kind`）だけでした。今回それを足しました。2,096 行の中身と日付は変えていません。

- 手順で作り直すと、次のように変わります（図 `canon_reproducibility_2026-10-24/structures_before_after.png`、数字は `structures_0828_vs_now.json`）。

### 4. 単線結線図が 1 回前の潮流で書かれていた

- `gen_sld` は枝の負荷率に潮流の結果を使います。ところが手順では潮流（`run_full_powerflow`）より前にあり、いつも 1 回前の潮流の結果で書いていました。
- 潮流の後へ移しました。clone からの確認で見つかりました。

### 5. 線を結ぶ変電所の多角形の選び方が、OS で変わっていた

- 手元（macOS）でバイト一致しても、CI（Linux・x86_64）で作り直すと正典が違いました。CI と同じ版のライブラリを手元に入れると一致したので、原因はライブラリの版ではなく OS でした。
- 研究室の Linux サーバーで同じ計算を流し、線の点ごとの結び付け先（約 37 万点）を比べました。違ったのは東京の 1 点だけでした。
  - その点を覆う多角形が 2 つあり、まったく同じ形でした（基底の 527 番と、補足ファイルに入っている重複の 1785 番）。
- 結び付け（と引込線）は、`STRtree.query` が返す候補を順に見ていて、最初に覆ったものか、距離が同じなら先に出たものを採っていました。
  - この順は木の中の順で、同じ版の shapely でも macOS（libc++）と Linux（libstdc++）で変わります。等しい値の並べ替えの結果が違うためです。
- 直し: 選び方を 1 つの関数 `_poly_pick` にまとめ、順に依らない決め方にしました。距離（覆っていれば 0）→ 面積の大きいほう → 番号の小さいほう、の順です。
  - 直したあと、`build_editor_data` の出力は macOS と Linux で全部バイト一致しました。
- **面積の大きいほう（外側の敷地）を選ぶ理由**:
  - 点を覆う多角形が重なる所は全国にあります。そのほとんどで、木の順では外側が先に出ていました。内側を選ぶ決め方を試すと 198 点が変わり、そのうち 188 点は名前の違う内側の多角形へ移りました。例は田端（東尾久五丁目の中）、西掛川（掛川電力所の中）、**南福光変電所（南福光連系所の中。#32 の BTB の分割が前提にするバス）** です。
  - 外側を選ぶと、変わるのは 32 点だけです。多くは同じ名前の重複や、同じ敷地の別名どうしでした。
- 正典への効き方（外側を選ぶ決め方）: ノード・枝の数は同じで、端点が動いた枝は 57 本です。4 島とも AC 収束のまま、#32 も当たっています。配布ケースは東の枝が 7,112 → 7,111 本で、他の島は同じです。
