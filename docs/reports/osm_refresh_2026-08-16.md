# OSM再抽出(大工事) 2026-08-16 — 基底データ刷新の実施記録

オーナー承認「大工事していい」に基づく基底データ(OSM抽出)の全面刷新。
判断・実装はAI(Claude Fable 5)。

## 動機

1. 現行抽出は**osm_idを持たず**、enrich結果(住所合成名等)がin-place混入([[project_agj_db_unification]]の核心問題)
2. **2025年以降のOSM新規マッピングが未反映**(九州プール突合で発覚: 苅田変電所・小倉圏の配電用変電所群=way ID 15億台)
3. 回線数タグ(circuits/cables)の充足率向上 — par→pandapower parallel→数値Ybusの経路は監査済みで健全、タグが新しくなるほど精度が上がる

## 実施内容(3フェーズ・全て再現可能)

1. **取得** `scripts/fetch_osm_refresh.py`(新規): 全10地域 lines+substations をOverpass直叩きで再取得。osm_id+全タグ保持・地域チェックポイント・生JSONも保存(data/osm_refresh/raw/ 34MB・untracked)
2. **移行** `scripts/migrate_osm_refresh.py`(新規): 旧をbackup_oldへ退避し、**名前資産を幾何一致で引き継いで**置換(OSM実名>旧enrich名>無名)。YAML台帳が参照する住所合成名(天瀬町赤岩変電所等)はOSM側が無名のままなら保存される設計 → 実測: **未解決ノード0・距離ガード発火0**
3. **再構築** regenerate_all ×2周(帳簿162本の介入+実線形吸着が自動再適用)

## 発見した設計欠陥と修正(罠17)

**route置換ペアのapplyスキップ防波堤が、フレッシュ再構築でコード12本を消した**。
ガードは「置換済みならスキップ」のつもりだったが、再構築直後はスタブも消えているため
「コードを二度と書かせない」ガードになっていた(第1周で実害・四国東部チェーン等が消失)。
修正: **正典に当該スタブが実在する場合のみスキップ**。検出は本系統外の勘定と
route「置換0」の組合せから。教訓: 防波堤は「適用済み状態」と「初期状態」の両方でテストする。
