# 発電機のゾーン帰属を座標で決めているせいで、大飯・高浜が出力3分の1になっている（2026-08-10）

介入#25（太陽光既定値）の適用可否を測る途中で、**ゾーンが供給不足になる島が1つある**
ことに気づいた（kansai: 容量 23,722MW / 需要×1.05 = 24,098MW = 比 0.98）。
追跡したところ太陽光とは無関係の、**出典を持っているのに捨てている**欠陥だった。

## 1. 何が起きているか

`balance_by_zone` はゾーン内の発電を需要に合わせてスケールする:

```python
z = net.bus.at[int(r["bus"]), "zone"]      # ← 発電機のゾーン = 繋がったバスの座標zone
scale = min(zone需要 × (1+予備率) / zone容量, 1.0)
```

発電機のゾーンを**繋がったバスの座標**だけで決めている。その結果:

| 発電所 | 出力 | 由来ファイル | operator（OSM） | 潮流上のゾーン |
|---|---:|---|---|---|
| 大飯原子力発電所 | 4,494 MW | `kansai_plants.geojson` | 関西電力株式会社 | **hokuriku** |
| 高浜原子力発電所 | 3,392 MW | `kansai_plants.geojson` | 関西電力株式会社 | **hokuriku** |
| 舞鶴火力発電所 | 1,800 MW | `kansai_plants.geojson` | 関西電力 | **hokuriku** |

計 **9,686 MW の関西電力設備が hokuriku の容量として数えられている**。
大飯・高浜は福井県、舞鶴は京都府にあるが、いずれも電気的には関西エリアである。

**モデルは答えを既に持っている** — 3 件とも `kansai_plants.geojson` 由来で
`operator` タグに関西電力と書いてある。`balance_by_zone` がそれを使っていないだけ。

## 2. 効果 — 個別出力は 3 倍ずれる、集計はほとんど動かない

hokuriku の容量/需要比は **5.00**（他ゾーンは 1.28〜4.4）なので
`scale = min(4,641/23,198, 1.0) = 0.20`。つまりこれらの機は**出力 20%** に抑えられる。
一方 kansai 自身の機は 78% で回る。ゾーン帰属を直すと:

| 発電所 | 現行 | 是正後 | 倍率 |
|---|---:|---:|---:|
| 大飯原子力 | 899 MW | **2,668 MW** | ×3.0 |
| 高浜原子力 | 679 MW | **2,013 MW** | ×3.0 |
| 舞鶴火力 | 360 MW | **1,068 MW** | ×3.0 |

west 全体の過負荷は **291 → 290 本**・最大負荷率 708.2%（不変）・
超過潮流 33,950 → 32,145 MW（−5%）。**集計はほとんど動かない。**

結論は二段構えになる:

- **個別の発電所出力を引用してはいけない** — 大飯 4,494MW の機が 899MW と出る。
  介入台帳「読み方」節の「バス別・線別の潮流値を個別に引用しない」に、
  **発電機の出力も加えるべき**。
- **集計の過負荷診断への影響は小さい** — 残る 853%/708% の説明にはならない。

## 3. 介入#24（既定ON済み）の副作用が 1,800MW ぶん含まれる

接続規則を `nearest` → `cap` に変えたとき、**ゾーンが変わった発電機は 8,775 機中 2 機**
だけだが、そのうち **舞鶴火力 1,800MW が kansai → hokuriku へ移った**（もう 1 件は
伊賀市発電所 10MW が kansai → chubu）。大飯・高浜は `nearest` の時点で既に hokuriku
だったので**既存の問題**であり、介入#24 が作ったのは舞鶴の 1,800MW ぶん。

`cap` は「受電容量が足りるバス」を探すので、**県境・エリア境界を越えて繋ぎ替えうる**。
これは介入#24 の帳簿に無かった副作用なので記録する。

## 4. 直し方 — 捏造ではなく、既にある出典を使う

`src/uc/capacity_bridge` は既に `gen_zone_override` を持ち、
`inject_dispatch_by_zone`（UC 経路）がそれを使う。設計意図も明記されている:

> zone override — region キー付きパッチ（敦賀火力→hokuriku、橘湾火力→shikoku）の
> 帰属表を返す。**bus.zone は需要配分に使われるため書き換えず**、
> inject_dispatch_by_zone が gen単位で上書きする

つまり**上書き機構は存在するが、`balance_by_zone`（本番の銘板比例経路）だけが
それを持っていない** — UC 経路と銘板経路の非対称。既存の上書き表にも
大飯・高浜・舞鶴は入っていない。

推奨（**未適用・人間判断**）:

1. `balance_by_zone` に発電機ゾーンの上書きを受け付けさせる（UC 経路との対称化）
2. 上書きの根拠は**モデル内の出典**に限る — 由来 GeoJSON のリージョンと `operator` タグ。
   外から帰属表を持ち込むと捏造になる
3. 需要側の `bus.zone` は座標のまま（`capacity_bridge` の設計意図どおり）

## 5. 実装した（介入#26・**既定OFF**）

`--gen-zone-by-operator` を用意し、台帳に #26 として登録した。既定の挙動は変えていない。

- `attach_generators` が OSM の `operator` タグから管内を引いて `zone_src` 列に持たせる
  （表は `src/uc/scenario.OPERATOR_REGION` を import＝写しを作らない）
- `balance_by_zone(use_zone_src=True)` がそれを使う。**需要側の bus.zone は動かさない**
- 帳簿: 実行ログ `介入#26 gen-zone-by-operator: 計上エリアを変えた N機/M MW`

### 全島での効果 — 集計は小さく、方向も混在

| 島 | 座標zone（既定） | operator帰属 | 変更 |
|---|---|---|---|
| hokkaido | 0本 / 86.0% / 0MW | 0本 / 86.0% / 0MW | 0機 |
| east | 551本 / 1,594.7% / 90,360MW | **544本 / 1,531.3% / 85,392MW** | 18機 / 5,556MW |
| west | 291本 / 708.2% / 33,950MW | 293本 / 708.1% / **35,993MW** | 73機 / 17,541MW |
| okinawa | 9本 / 165.0% / 211MW | 9本 / 165.0% / 211MW | 0機 |

east は微改善（超過 −5.5%）、west は微悪化（+6%）。**これは過負荷を減らす梃子ではない。**
価値は「大飯 4,494MW の機が 899MW と出る」のをやめられることにあり、
**個別発電所の出力の正しさ**のための修正である。台帳「読み方」節に
「発電機の個別出力を引用しない」を追加した。
