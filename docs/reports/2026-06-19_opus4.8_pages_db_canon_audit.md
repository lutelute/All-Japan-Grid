# Pages 各タブの「DB正典忠実度」監査 — built/ を正とした時の違和感の同定

作成: 2026-06-19 / **Claude Opus 4.8** / オーナー指摘「DBを統合した。これからそれを正とした時に、今のpagesのツールに対する違和感があちこちある。評価してほしい」。

## 0. 結論（ひとことで）

**表示の正は `built/` に移ったが、属性とモデルの正はまだDB外の旧世代ファイルに残っている**——この二層構造が違和感の根。各タブは「**幾何は built、中身は旧ファイル**」という接ぎ木で動いている。エディタ・Ybus は正典に追従済みだが、系統図の属性・潮流タブ・SLD が旧世代に取り残されている。

## 1. 監査方法

- 読取専用。`docs/index.html` のタブ構成（map/area/pf/sld/compare/ybus/editor/review）を起点に、各タブのJSが実際に `fetch()` するパスを行番号で特定し、その出自（built派生か／旧基底OSM抽出か／旧縮約モデルか）と生成日・件数・フィールドを実測で突合した。
- 一次根拠（件数・日付・行番号）は §6 に集約。憶測は排し、コードとファイルから読める事実のみを根拠とした。

## 3. 違和感の構造（本質的な順・一次根拠つき）

### ① 属性の「正」がDBの外にある — 最も構造的、DB統一理念と正面衝突
- `built` 正典の変電所は**4フィールドのみ**（`_region`/`_region_ja`/`_display_name`/`_voltage_kv`）。operator・category・電圧根拠（`voltage_source`）・周波数といった運用属性は、いまだに**旧 `substations.geojson`（3/6・6,962件・15+フィールド）にしか無い**（`grid_map.js:692`）。
- built表示は **8,994件**、旧属性ファイルは **6,962件**。差の**約2,000変電所はクリックしても詳細が引けない**。両者は座標一致（`lookupEnrichedSub` `grid_map.js:479-481`）で後付け接続しているだけで、build再生成で座標が動けば対応が外れる。
- これは [[project_agj_db_unification]] の R/C/D 3層化（属性=C層・表示=D層派生）の**積み残し**を、最も見られるタブがそのまま晒している状態。「DBを正にしたい」のに属性の正は旧GeoJSONに居残っている。

### ② 潮流タブが3世代モデルの同居
- 1つのドロップダウンで `full`(17,333・正・`PF_DIR=powerflow_full/` `powerflow.js:288`) / `national_backbone`(**旧縮約2,189バス matpower**・`powerflow.js:573,600,644`) / `national_zonal`(別モデル・DC固定・`powerflow.js:858,879`) を切替える。コードは用途分離で正しく書けているが、**ユーザー視点では選択肢で"正典度"がサイレントに後退**する。「DBを正にした」のに *全国基幹* を選ぶと旧2,189バス（`topology:"snapped"`）へ戻り、*全国ゾーン* はDC固定（west非収束のため）。

### ③ SLDタブが旧世界に取り残し
- `sld.js:185` が `./data/powerflow/sld_data.json`（旧縮約由来）を読む。フィールドも旧（`buses[].kv` であって built契約の `_voltage_kv` でない）。built由来化が唯一されていないタブ。

### ④ 発電所が丸ごとDB正典の外
- `built/all.json` は送電網（変電所+接続点+線）のみ。発電所は `plants_*.geojson`（4/23・19,138件）として完全別管理。「全系統を1つのDBで」を突き詰めると、発電所はまだDBに入っていない。

### ⑤ データの遺物堆積
- `powerflow_snapped/` と `powerflow.legacy_*`×4 = **5ディレクトリが完全死蔵**（docs/js・docs/*.html からの参照0件）だが公開デプロイされ続けている。（`powerflow_before/` は `compare.html:61` が使用中なので別扱い）

### ⑥ バージョン刻印の形骸化
- `MODEL_VERSION.json` は `92eb0f6 / 2026-06-16 / git_dirty:true`。その後 `powerflow_full`(6/18)・`built` 等が個別更新され、「単一モデルから一括再生成」(全面改修Phase4)の不変条件が崩れ、版票が実態とずれている。

## 4. 着手対象（オーナー選択 2026-06-19）と是正方向

オーナーは **①②③** を着手対象に選択（④⑤⑥は今回見送り）。各々の是正方向（設計は次工程・本レポートでは方針のみ）:

- **① 属性をDB正典へ（本丸）**: built正典に運用属性を載せる、もしくは安定キー（`g:{geom-sha1}` 等）でC層（`enrichments`）と結合してD層exportに属性を含める設計。`export_map_tiers_from_built.py` の出力契約に属性列を追加する経路が有力。座標一致接続を廃し、件数差（8,994 vs 6,962）由来の欠落を解消する。[[project_agj_db_unification]] のC/D層をUIまで通すのが核心。
- **② 潮流タブの正典統一**: 3世代モデル同居を整理。`national_backbone`(旧縮約2,189)/`national_zonal` の扱いを決め、UIで正典度がサイレント後退しない構成（例: 旧モデルは明示ラベル分離 or 正典由来へ再生成）にする。
- **③ SLDをbuilt由来化**: `sld.js` を `powerflow/sld_data.json` から built正典由来データへ移行。フィールドを built契約（`_voltage_kv` 等）に揃える。

## 5. 今回着手しない項目

- **④ 発電所のDB取り込み**: P03権威データ（[[project_agj_db_unification]] §Step4）と接続する大きな設計。①の属性層化と連動しうるが今回スコープ外。
- **⑤ 遺物お掃除**: 死蔵5ディレクトリ撤去・`MODEL_VERSION` 再刻印。低リスク・即効だが今回見送り。
- **⑥ 版票整合**: ⑤と同時に処理すべき軽微項目。
