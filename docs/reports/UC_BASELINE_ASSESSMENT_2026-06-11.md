## 3. 計測で確定した問題（優先度順）

1. **地域スライス重複の二重計上** — 126機39.8GW。osm_idで機械的に除去可能。最も安価で効果大。
2. **揚水がstorage表現されていない** — OSM抽出が `plant:method`（`water-pumped-storage`）を保持しておらず、
   揚水が全て一般水力(fuel_cost=0)に落ちる。`scenario.py` の `is_storage = fuel in ("pumped_hydro",)` は
   現データではデッドコード。大規模揚水は名前で同定可能（葛野川1600/奥清津1600/奥吉野1206/玉原1200/
   今市1050/神流川940/塩原900/沼原675/喜撰山466/京極400 等が data 内に現存、地域重複込み）。
   日本の揚水実態は約27GW — これがUCの柔軟性資源として完全に欠落している。
3. **原子力の稼働状態が未反映** — 27機35.9GW全てが起動可能。実態（再稼働済み≈12基）との照合が必要。
   P03 2013年版の陳腐化（鹿島5.7GW等の廃止反映漏れ）も同系統の問題。
4. **設定の二重管理** — `FUEL_COST` 等が scenario.py（旧 gen_uc_regional.py）ハードコードで、
   `config/uc_config.yaml` と不一致（例: pumped_hydro 0 vs 2000）。yaml読み込みに一本化すべき。
5. **HiGHS未導入** — `solver_name="highs"` 指定だが highspy 不在で CBC にフォールバック。
   636機24hで31.9s。8760h化・台数増の前にHiGHS導入が必要（pip install highspy で済む見込み）。
6. **蓄電池が地域1台集約** — OCCTO参照値ハードコード。実サイト分布（OSM/系統用蓄電池の公開リスト）
   との照合は中期課題。
7. **沖縄スタンドアロン発電機がスクリプト内ハードコード** — gen_uc_regional.py 固有。データ層に移すべき。

## 4. 今回整備した計測基盤（このcommit）

- `src/uc/scenario.py` — gen_uc_regional.py のロード部を共通化（**挙動不変を出力一致で確認**:
  636機/268,361MW/全需要数値/沖縄¥206.9百万が一致、総コストは¥67.99→68.00億でgap内）。
  `LoadStats` でロード時品質統計（重複・補完・storage）を自動収集。
- `scripts/uc_benchmark.py` — データ品質+求解+ディスパッチKPIのスナップショットを
  `docs/reports/uc_benchmark_<label>_<date>.json` に出力。`--baseline` で差分表示。
- `tests/test_uc_scenario.py` — 11テスト。既知課題（重複の二重計上・揚水の非storage扱い）を
  回帰ピンとして明示（改善時に意図的に書き換わることを保証）。
