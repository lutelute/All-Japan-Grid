# 併架線の回線数を、線路名ごとの証拠で電圧クラスに配る(ビルダー修正)

2026-09-21 ・ **Claude Opus 5** ・ オーナー指示「源泉で電圧ごとに回線数を分けるのをやって」

発端は南海トラフの鹿島の過負荷追跡 → [`nankai_hazard_2026-09-13/dynamics/mixed_voltage_circuits_2026-09-21.md`](nankai_hazard_2026-09-13/dynamics/mixed_voltage_circuits_2026-09-21.md)。
そこでは `hazard/nankai` 側の局所的な是正(`branch_parallel`)だったが、本件は**源泉(`src/powerflow/snapped_topology.py`)での恒久修正**。

## 何が起きていたか

OSM は同じ鉄塔に別電圧の回線が乗る線路(併架)を 1 本の way にまとめ、電圧と回線数を併記する。

```
name=香取線 / 湖南線   voltage=275000;66000   circuits=6
```

これは **275 kV 2 回線(香取線)+ 66 kV 4 回線(湖南線)** の意味。旧実装は:

```python
circ_eff = circ if (len(build_classes) == 1 or bkv == kv) else 1
```

= **主クラス(最大電圧)が合計 6 を全部持ち、展開した下位クラスは 1 回線**。結果として 275 kV が 6 回線ぶんの容量(5,716 MW)を持ち、66 kV は 1 回線に過小評価されていた。

旧実装のコメントは、この選択の理由を「下位を 1 にすると主送電容量が激減し過負荷になる(関西『国府支線;岩中国府線』77;33 circuits=3 を 77 kV 側 3→1 にしたら 184% 過負荷)」と記している。**「合計を主クラスに残す」か「1 にする」かの二択**になっていた。

## 直し方: 線路名ごとの回線数を、単一電圧の way から読む

同じ線路の**単一電圧区間**がデータの中にあれば、それがその線路自身の回線数の直接証拠になる。

```
name=香取線   voltage=275000   circuits=2      ← 香取線は 2 回線
name=湖南線   voltage=66000    circuits=4      ← 湖南線は 4 回線
```

実装(`mixed_voltage_circuits_by_name=True`・既定有効):

1. `_voltage_class_list(voltage)` — タグの**順番どおり**の kV クラスの列(既存の `_parse_voltage_classes` は集合なので名前と対応が取れない)
2. `_line_name_list(name)` — `香取線 / 湖南線` や `秦浜線;湘南線` を線路名の列に。OSM は電圧と線路名を同じ順で並べる慣習
3. `_circuit_evidence(props, min_support=2)` — **単一電圧・単一名・`circuits` タグあり**の way だけから `{(線路名, kv): 回線数}` を作る。値が割れたら最頻値、同数なら大きい方(過小評価を避ける)。**2 本以上の way が支持する値だけ**採る(区間端の 1 回線だけの引込を全線に広げないため)
4. 配分は**タグの合計回線数を保存**する。証拠のあるクラスはその値、残りを証拠の無いクラスで等分(最低 1)。**証拠の合計がタグを超えるときは配分せず従来どおりに落とす**(推測はしない)

証拠が無ければ従来の挙動に落ちるので、データが増えるほど正しくなる。

### 懸念だった関西の事例

`国府支線;岩中国府線` `77000;33000` `circuits=3` は、旧実装が恐れた「77 kV 側を 1 にする」ではなく **3 → 2**(証拠)、残る 1 が 33 kV 側に回る。合計 3 は保存される。

## 3 点セット(介入台帳の要件)

- **①根拠**: OSM の単一電圧・単一名 way の `circuits` タグ(2 本以上の支持)。検算として、東京電力 系統情報公表の潮流実績の線路名(`1･2L` = 2 回線)と一致することを鹿島の回廊で確認
- **②帳簿**: `net.mixed_voltage_circuit_fixes`(線路名・電圧・タグの合計・前後の回線数)と `net.metadata["mixed_voltage_circuit_fixes"]`(件数)
- **③無効化**: `build_network_snapped(..., mixed_voltage_circuits_by_name=False)` で旧挙動

`docs/MODEL_INTERVENTIONS.md` への登録は**別アクターの未コミット編集が残っているため保留**(変圧器台帳の介入と同じ扱い)。

## まだやっていないこと

- **正典(`docs/data/built/`)は再生成していない。** ビルダーのコードは直ったが、下流(Ybus・MATPOWER・pages・ハザードモデル)が読む正典は旧の回線数のまま。再生成は Ybus → MATPOWER の連鎖再生成を伴うのでオーナー判断
- 過負荷 KPI(`ajgrid validate --topology --solve`)での前後比較。旧実装が恐れた 184% 過負荷が再発しないことは、`国府支線` が 3→2(1 ではない)で合計も保存される設計から**構造的には避けられているが、実測はしていない**
- 名前と電圧の順番の対応は OSM の慣習に依存する。逆順のタグがあれば誤配分しうる(現状は検出していない)
- `circuits` タグが無い併架線は従来どおり(証拠なしは触らない)
