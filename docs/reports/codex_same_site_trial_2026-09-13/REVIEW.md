# 敷地・枝端・電圧別母線を分けた系統モデルの試行

実在する変電所の位置と電気的なバスの位置を一つの座標へ押し込むと、敷地外の代表点へ線が寄せられ、断片・誤った引込・消えた設備のように見える。**今回は「元モデル／13組の単純同定／敷地と枝端を分ける第三案」をHTMLで比較できるようにした。全27組の航空写真を実際に目視し、初期13組のうち5組は引込先の再追跡へ戻した。**

第三案は `src/powerflow/site_terminals.py` で実装。入力17,738ノード・19,944枝を保持する。元OSM敷地、電圧別モデル母線、保存線形の枝端、未解決の所属を別に記録し、接続仮説をIDで回路へ投影する。34バスの表示座標を敷地代表点へ戻しても、単純同定案と電気テーブルが一致し、**固定注入のDC枝潮流差は0 MW**だった。異電圧母線は同じ地理座標へ表示しても別バスとして残る。これは表現を座標依存から分離できることの検証で、13組の実配線の確認完了ではない。ACは元の13組試行と電気的に同一なので表示変更のためには再実行していない。先行する固定条件ACの未収束が残る。

## 第三案のデータと検証

- **Site**：OSMの敷地形状と表示用の内部代表点。代表点は母線の実測座標ではない。
- **Bus**：電圧別の計算要素。接続はIDで指定し、同じ表示座標を持つだけでは統合しない。
- **Terminal**：既存ビルダーが割り当てた枝端と、その保存線形の端。元の接続判断を追跡可能な仮説として記録する。
- **Unresolved**：線形欠測、敷地外終端、電圧不明、所属未確定。設備や枝を削除せず、必要な追加根拠を残す。

今回の対象に属する枝端は70。内訳は敷地内終端10、25m以内3、敷地外33、保存線形なし21、敷地境界不明3。送電線だけでなく推定引込・サイト内の枝も含むため、実機端子70個を確認したという意味ではない。保存pathには以前のOSM連鎖再構成なども含まれ、すべてを直接観測線と扱わない。近接・敷地への交差だけでは導通を認定しない。通過線は端点を切って自動接続しないこともテストした。

`site_terminals.json` は24個の元サイトを含む照合表。回路への投影対象は東日本の23サイト・34表示バスで、`site_terminal_verification.json` に電気テーブル比較とDC検証を記録した。線路6,467本・変圧器677台・負荷55,250MWは単純同定案と同一。元の観測・モデル記録と計算用の集約を分けて保持する仕組みであり、正典の自動統合処理には組み込んでいない。

## 保存線形の重複を検出

秩父の枝5923「宮地線」は、保存線形9区間すべてが復元枝19942にも含まれる。共通部分は約1.350934km。前者は2回線、後者は1回線と記録され、復元枝には「6way・継ぎ目最大194m」という来歴がある。**点を統合するだけでは、同じ区間の二重計上や途中の分岐の扱いは解決しない。**

端子に割り当てられた枝と全国の保存線形を照合し、同じモデル電圧・座標5桁で同じ無向区間が3以上・短い方の区間数の50%以上を共有する組を42組検出した。`path_overlaps.json` に全件、HTMLに地図上の黄色い重ね合わせと全件閲覧を収録。実際の並列回線は同じ線形を取り得るため、42組を誤回線の確定件数とはしない。元way・OSM node・回線IDへ戻り、共通区間と専用区間、実在する途中端子を分けて構成する次の調査対象となる。

## 発想と方法

座標だけでの重複除去は、同じ元設備の代表座標が地域ごとにずれると取りこぼす。`snapped_topology.py` は敷地中心を初期値にし、線端を束縛した場合はその平均へ代表点を移す。同一設備でも地域ごとに線端の集合が異なれば代表点がずれる仕組みがある。ただし、今回すべての点の生成履歴を再現したわけではない。

照合ではビルダーと同じ「地域の基底GeoJSON＋補足GeoJSON」の連番規則を再現し、名称・位置・元のOSM IDを検査した。連番は将来の再生成で変わり得るため、元ファイルのSHA、feature index、OSMのtype/id、幾何ハッシュを保存した。現在の入力での同定であり、近接や同名だけで設備を確定する規則にはしていない。

試行した統合は、既存モデルの「同じサイト・同じ電圧階級を1バスとする」抽象化内の重複同定。実変電所の複数母線・母線連絡器・遮断器の開閉状態を追加した操作ではない。13組とも元OSM IDと同一の正のモデル電圧を確認し、うち5組は元の電圧タグも一致する。残る8組は電圧タグ欠測のため、モデル階級を維持する条件付き試行として区別した。

## 試行途中で見つかった副作用と修正

最初は、バスを統合した回路と、同定後builtから組み直した回路の線路パラメータが一致しなかった。`powerflow_attempt1.json` がその記録。

原因はbuilt枝10781（leadin）。保存pathがないため、ビルダーはバス端点の距離で長さを推定する。渋川市の点を同定すると、長さが **1.034420 km→0.993076 km** に変わった。接続の同定とインピーダンス変更を混ぜないため、元の推定に用いた端点を `identity_length_reference` として保存し、ビルダーがその参照から長さを計算するようにした。保存pathは作り足していない。この項目のない既存データの計算方法は同じ。

修正後、線路6,467本・変圧器677台について、統合した回路と独立再構築した回路の接続先と比較対象パラメータが全件一致した。比較項目は `solve_same_site_trial.py` の `fingerprint` に列挙。長さ・R/X/C・電流定格・並列数・運用フラグ、変圧器の定格・短絡電圧・損失・位相・タップ等を照合した。

## 同じ注入値での計算

東日本の実ビルダーから回路を作り、地域需要配分と発電機配置を一度だけ実行。負荷 **55,250 MW / 18,159.796811 Mvar**、発電の有効電力設定 **58,012.5 MW**、無効電力補償係数0.8を全条件で保存した。個別の負荷・発電・shuntの行は接続先バス以外すべて同一であることを確認。地点需要の再配分、負荷切捨て、新しい仮給電、低圧網の縮約は行っていない。

統合先には両コピーの負荷が合算される。これは構造だけを比較する実験上の条件で、実際の設備需要を確定したものではない。1成分ごとにslackを置く既存の仮定が残り、実電源から供給できることの証明ではない。

- DC：3条件とも成立し、配分需要55,250 MWを保持。13組試行後の最大枝潮流差は **277.344 MW**。線ごとの値はHTMLとJSONに記録。
- AC：NR、DC初期値、50反復、許容残差10⁻⁴ MVA、発電機Q制約あり、という同一条件で3条件とも未収束。緩い許容値やDC代替をAC成立として扱わない。
- 東日本の異電圧line62本は全条件で同じindex集合のまま。最大DC負荷率も約878.09%で残る。これらは今回の同定だけでは解消しない問題であり、AC未収束の真因を確定した結果ではない。
