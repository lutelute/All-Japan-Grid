# 発電容量の出典はどこまで届いているか（2026-08-09）

> **現況（2026-08-11 追記）** — 記録は書いた瞬間の写真なので本文は変えない。その後どうなったかだけをここに足す。
>
> **指摘①（発電容量の出典が CGMES に届いていない）は 2026-08-10 に解消した**。R層は書き換えず読む側が D層を引く形（単一出典 `src/capacity_sources`）で、kyushu_EQ だけで出典URL 192種・全体で発電容量DB由来 291種が刻まれている。指摘②（出典値の多重計上）は未対応のまま。

出典必須DB は値と出典をセットで持つが、**その値が下流のどの成果物に届いているか**は
別問題。監査したところ二つの穴が見つかった。

## ① 発電容量の出典が CGMES に届いていない

| | |
|---|---:|
| 発電容量 出典DB の URL 種類 | 336 |
| 変圧器 出典DB の URL 種類 | 35 |
| CGMES 内の出典URL（延べ / 種類） | 13 / 9 |
| うち **発電容量DB** 由来 | **0** |
| うち 変圧器DB 由来 | 9 |

CIM が読む `data/*_plants.geojson` は 19,138 レコードあるが、
`capacity_mw_sourced` を持つのは **0 件**。

`src/cim/exporter.py` は出典値を優先し出典URLを `IdentifiedObject.description` に
刻む実装になっている（Phase 1-B 出典伝播）。しかし出典を書き込む
`apply_capacity_sources.py` の対象は `docs/data/` の 4 ファイルだけで、
**CIM の入力は対象外**。つまり伝播の経路が繋がっていない。
変圧器の出典は別経路で届いているため、CGMES に出典URLは存在する — 
そのせいで「届いている」ように見えてしまう点が厄介だった。

**影響**: CGMES の `GeneratingUnit.ratedP` は出典付きの値ではなく OSM/P03 由来の
生値のまま。捏造防止の規約が CGMES まで貫通していない。

## ② 出典値を単純合計すると多重計上になる

`docs/data/generators.geojson` の 304 件が出典付きで、
実体は **111 発電所**（うち 75 発電所が複数レコード＝号機単位）。

| 数え方 | 合計 |
|---|---:|
| 号機容量 `capacity_mw` の合計 | 205,446 MW |
| 発電所ごとに 1 回だけ数えた出典値 | 174,287 MW |
| **レコード単位で出典値を合計** | **650,572 MW** |
| 多重計上ぶん | 476,285 MW（73%） |

`capacity_mw_sourced` は**発電所全体の値**（柏崎刈羽 8,212MW = 7 号機合計）だが、
レコードは号機単位なので同じ値が 7 レコードに載る。**現時点でこれを合計している
消費者は無い**ので実害は出ていないが、集計を書いた瞬間に踏む罠として残っている。
