# 潮流実績と OCCTO の公表を最新に保つ 2026-10-24

オーナー指示：「どんどん最新になっていけるように」「OCCTO の潮流実績が更新されない問題も解消して」。

調べると、止まっていたのは 2 つだった。どちらも取得のスクリプトはあったが、手で回すだけで、定期的に回す仕組みが無かった。もう 1 つ、潮流マップの「観測と比べる」が線を重ねて数えていたことも見つかった。

## 1. OCCTO の系統情報公表（エリア需要 02・連系線 04 の 30 分値）が 2026-06 で止まっていた

- 手元の蓄積 `data/external/occto/` は、2026-06 の途中（753 KB）で止まっていた。
- OCCTO の API はおよそ 14 か月分しか残さないので、取り損ねた月は二度と取れない。
- 2026-06-01〜10-23 を取り直した（`kohyo_02`・`kohyo_04` の各 5 か月分）。
- **毎時の処理（`scripts/realtime_cycle.sh`）で、日に 1 回、当月を取り直すようにした。** 月初の 3 日は前月も取る。
- 置き場は本体のチェックアウト（毎時の処理の worktree からはリンクの親を使う）。
- 日別の断面に入れている連系線の計画潮流（`fetch_area_fuelmix.py` が日ごとに取る `kohyo_04`）は、止まっていなかった。毎日 24 時間分そろっていた。

## 2. 各社の系統情報公表（潮流実績）を取り込んでいなかった

### 取りこぼしていた公表

| 社 | 取りこぼし | 原因 |
|---|---|---|
| 関西 | 2025-06 の公表（基幹） | 取得を回していなかった |
| 東北 | 2025-02 の公表（31 ファイル） | 同上 |
| 沖縄 | 2 ファイル | 同上 |
| 中部 | 12 ファイル（直リンクの一覧） | 設定は `direct_urls`（一覧）なのに、取得のコードは単数形の `direct_url` しか読まず、**一度も自動では取られていなかった** |

- 2025 年度分（2026 年夏の公表）は、各社の公表ページを直接見てもまだ出ていなかった。2026-10-24 時点の最新は、四国 2025-08・中国 2025-07・関西 2025-06・北陸 2025-05・九州 2024-09 の公表。

### 取得を直した

- 中身が前回と同じファイルは書き直さず、記録もしない。新規・更新だけを数えて `--changed-file` に書く。
- 置き場は環境変数 `AGJ_SYSTEM_DISCLOSURE` で変えられるようにした。
- 取り直した結果：120 ファイルのうち新規・更新 46、同じ 74。

### 毎時の処理に組み込んだ

- 週に 1 回、公表を確かめる。
- 新しい公表があれば、次の 3 つを自動で作り直す。
  - 観測の表（`build_line_observations.py`）
  - 公開している「観測と比べる」（`obs_compare.json`）
  - 地方系統の観測（`obs_local.json`）
- 作り直した 2 つは、毎時の公開で main に出る。

### 観測の表の変化

| | 前 | 後 |
|---|---|---|
| 行（線 × 公表の年） | 8,726 | 9,121 |
| 運用容量まで突き合わせた行 | 1,723 | 4,232 |
| 3 様式（潮流・容量・インピーダンス）すべて | 46 | 284 |

運用容量の増加（北海道 349・北陸 22・東北 2,039）は、同じ線の行に容量が付いたもの。各社の空容量一覧は 10-07 に手元へ取ってあったが、観測の表はその前に作ったまま、作り直されていなかった。

## 3. 「観測と比べる」が同じ線を公表の年ごとに重ねて数えていた

- 観測の表には、同じ線の行が公表の年ごとにある（関西は 2018〜2025 年の公表）。
- 照合はそれを全部、別の線として数えていた。
- **これまでの「照合できた線 1,752 本」のうち 908 本は重なりで、異なる線は 844 本だった。**
- 観測の表の各線の最新の公表に `is_latest` を付け、使う側の 3 つはそれだけを読むようにした。過去の年の行は表に残す。
  - 観測と比べる
  - 地方系統の観測
  - 毎時の向きの照合

| | 前 | 後 |
|---|---|---|
| 照合の行 | 1,752 | 789 |
| 異なる線 | 844 | 742 |
| 向きの一致（UC / 実績需要） | 0.670 / 0.725 | 0.677 / 0.731 |
| p95 が 2 倍以内（UC / 実績需要） | 0.518 / 0.538 | 0.509 / 0.547 |

- 一致の割合はほとんど変わらない。照合の結論は変わらず、数だけが水増しされていた。
- 残る 47 本の重なりは、多くが別の線として正しいもの。
  - 東京は電圧別と県別の両方のファイルに同じ線が載る形式。
  - 中部は電圧違いや、番号の振り直し。
- 潮流マップの「2024 年度」という手書きの表記を外した。各線の説明には、元にした公表ファイルの名前（公表した年月が入る）を出す。

## 検査

`tests/test_observations_fresh.py` を足した。次のどれかが起きると落ちる。

- 毎時の処理から、OCCTO と潮流実績の段が消える
- 作り直した観測が公開されない
- 中部の一覧を読まない
- 照合で同じ線が 1 割を超えて重なる
