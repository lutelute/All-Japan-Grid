# モデル・ソース統一設計 — 全国/地域/編集を「単一の正」へ

**起票**: 2026-06-16 / **モデル**: Claude Opus 4.8 / **発端**: オーナーの実機レビュー(手作業で接続編集中)で判明した構造的混乱。
オーナー指摘(2026-06-16, 原文要約):
- 「全国で見た時と地域で見た時でなぜ接続が異なるように見えるの？修正」
- 「model本系統(青)・接続線(水)はかなり良く繋がっているのに、なぜ全体に反映されない? DBが異なるなら明記すべき。修正も反映もどれが正かわからず煩雑。**設計整えてほしい**」
- 「他地域との連携や所有は2〜3エリアで容認しないと島は消えないし接続が切れて見える」
- 「**共有鉄塔も絶対あるはず**」

---

## 1. 根本原因 — 3つの別データ経路を別々に描いている

| 表示 | データ源(現状) | 編集を映す | モデル接続を映す | 越境線 |
|---|---|---|---|---|
| 全国(all) | 生OSM geojson(≥66kV・全地域マージ) `get_all_geojson_light` | ❌ | ❌ | ✓丸ごと |
| 地域・OSM層(灰) | 生OSM geojson(地域) `get_geojson` | ❌ | ❌ | ✂県境で切れる |
| 地域・モデル層(青/水) | `build_network_snapped`+supplement+cuts `/api/built` | ✓**ここだけ** | ✓ | ✂地域別buildで切れる |

**帰結**: 人間の修正/反映(supplement/cuts)は「地域のモデル層」にしか出ない。全国ビューも地域OSM層も別ソースの生OSMを読むため**永遠に反映されない**。「どれが正かわからない」の正体=**単一の正(source of truth)が存在しない**。

## 2. 確定した事実(計測)

- okinawa OSM線は117本すべて電圧タグ付き(66kV 69・132kV 25・132;66 17・無6)。オーナーが手トレースした`伊芸~松田線`等は**OSMに実在・タグ付き**。データ欠落ではない。
- 手作業118接続を入れてもモデル枝 114→113(**−1**)。線が既に在るため**既存頂点にスナップ吸収・重複統合**された。→「繋いだのに消えた」の正体。
- 地域別buildが県境で線を切る(越境スライス断片)。→ 越境変電所が島化。
- 標準ツール(osmnx)検証済(台帳134): 座標スナップはOSMノード共有(=共有鉄塔)を取りこぼさない。**共有鉄塔は原理的に捕捉できている** — 問題は描画と地域分割。

## 3. 要件(オーナー, 2026-06-16)

- **R1 単一の正**: 全国も地域も「OSM基底+反映済み編集 → build したモデル」という**同一ソース**を描く。全国=地域の絞り込み(必ず一致)。
- **R2 越境容認**: 隣接2〜3地域を県境で stitch して build。越境線・複数地域所有の変電所を繋ぐ(島を消す)。
- **R3 共有鉄塔**: 複数回線/事業者が共有する鉄塔を**1つの接続点(junction)**として faithful 表現。分岐を潰さない。
- **R4 編集フロー一本化**: 修正=意図記録 → 反映=唯一の正へ永続 → 1回再build → 全ビュー同時更新。
- **R5 来歴明記**: 各線/点に「OSM由来/人間追記/推定」をUIで明示。「DBが違うなら明記」への対応。
- 不変条件(継承): OSM=真・計算は検証器・捏造禁止・基底extract不変・committedスコアカード不可触。

## 4. 目標設計

```
   OSM基底(不変)  +  curated編集(supplement/cuts = 人間の物理確認)
                    │
                    ▼   ★唯一の"正"(1回のbuild)
        全国を一枚で build(隣接県境を stitch・共有鉄塔=共有ノードで junction 化)
                    │
        ┌───────────┴───────────┐
   全国ビュー              地域ビュー
   = 同じモデル           = 同じモデルの絞り込み(地域bbox)
   (編集も越境も共有鉄塔も、全ビューで一致)
```

- **正は1つ**: `built = build(OSM + adopted edits)`。`/api/built` を全国にも拡張し、全国ビューも生OSMでなく built を描く。
- **共有鉄塔**: 既存の頂点グラフ(prec4座標丸め=OSMノード共有)で junction 化済み。描画側で degree≥3 のノードを「共有点」として明示(畳まず見せる)。
- **越境**: 全国 build は地域を merge し、県境近傍の端点を stitch(隣接2〜3地域だけを対象に近接スナップ)。
- **来歴**: built の各枝に `provenance`(osm/human/inferred)を付与済 → UIで色/ラベル化。

## 5. 段階実装(branch `model-source-unification`)

- **Phase 1(最優先・即効)**: 全国ビューを built モデル(編集込み)で描くよう統一。`/api/built/all`(= 全地域 build を merge)を追加し、`loadNational` をそれに切替。→「全国に反映されない」即解消・全国/地域の一致。
- **Phase 2**: 県境 stitch(隣接地域 merge build + 境界近接スナップ)で越境島を解消。A/B(島数・ρ・AC)。
- **Phase 3**: 共有鉄塔 junction の明示描画 + 来歴ラベル + 編集フローUIの一本化(「正」を画面に明示)。

各 Phase は独立コミット・full pytest 緑・A/B 計測・悪化 revert・before/after 図。本番(main)へは検証後にのみ統合。

## 6. 未決(オーナー判断)

- 全国 build の重さ(全地域 merge)→ キャッシュ戦略。Phase 1 は地域 built の合成で軽量に開始。
- 県境 stitch の許容距離(越境スナップ閾値)→ 偽接続を作らない範囲で計測決定(台帳の3,365誤接続の教訓)。
