# observed と derived を分ける — 同名の量を混ぜないための規約

**確定方針（オーナー指示 2026-08-11）**
> 「空き容量とかは、解析で出てくるものでもあるから、解析で出てくるものと分けておくことも必要。」

空容量・潮流・過負荷率は、**事業者が公表している値**でもあり、**AGJの解析が出力する値**でもある。
名前が同じで単位も同じなので、放っておくと混ざる。混ざった瞬間、
「これは検証されたのか、それとも自分の計算結果なのか」が言えなくなり、DBの信頼が崩れる。
両者を**層として分離**し、同一テーブルに同居させない。

---

## 1. 二つの層

| | **observed（公表値）** | **derived（解析値）** |
|---|---|---|
| 何 | 一般送配電事業者・OCCTOが公表した実績・諸元 | AGJのPF/N-1/PTDFが計算した値 |
| 出所 | 出典URL・公表日・取得日・様式番号が必ず付く | 入力モデル版・ソルバ・介入セットが必ず付く |
| 置き場 | `data/external/system_disclosure/`（gitignore, 再配布しない） | `docs/data/powerflow/`, `docs/data/n1/` 等 |
| 真偽 | **参照される側**。AGJの都合で書き換えない | **検証される側**。observedに対して誤差を測る |
| 更新 | 事業者の公表に追従（`scripts/fetch_system_disclosure.py`） | モデル再計算で作り直す |

### 同名で衝突する量（要注意リスト）

| 量 | observed の出どころ | derived の出どころ |
|---|---|---|
| 空容量 (MW) | 様式「空容量一覧」/ 空容量マッピング | 運用容量 − PF潮流 |
| 運用容量 (MW) | 様式（制約要因つき: 熱容量/安定度限界/電圧安定性） | 導体諸元からの熱容量理論値 |
| 潮流 (MW) | 様式「潮流実績」(8760時間) / 予想潮流 | DC/AC潮流計算結果 |
| インピーダンス R,X,B | 様式5（1000MVAベース %） | 線種・こう長からの推定値 |
| 過負荷率 (%) | （公表されない） | derived のみ |

> **運用容量の観測は特に重い。** 既知のとおり導体から引いた理論値は運用容量の**約2倍**になる
> （[[project_agj_capacity_calibration]]）。observed の運用容量には *制約要因* が付いており、
> 熱容量ではなく**安定度限界**で決まっている線が実在する（四国 500kV: 設備容量6,580MW に対し
> 運用容量2,060MW = 31%、要因「安定度限界」）。理論値では原理的に到達できない値であり、
> derived が observed を代替できないことの実例。

---

## 2. 規約

1. **derived は observed を上書きしない。** モデルに公表インピーダンスを採用する場合も、
   それは「observed を入力として選んだ」という介入であり、
   `docs/MODEL_INTERVENTIONS.md` に①根拠②帳簿③無効化の3点で登録する
   （[[feedback_intervention_registry]]）。
2. **列名に層を残す。** 突き合わせ表では `x_observed` / `x_derived` / `x_ratio` と並べ、
   素の `x` は作らない。素の名前は「どちらか分からない」を意味してしまう。
3. **出典なき observed は observed ではない。** 出典URL・取得日を欠く行は
   provenance 欠損として REJECT する（[[project_agj_capacity_provenance]] の機構を流用）。
4. **比較は専用ビューでのみ行う。** 突き合わせは `scripts/compare_observed_derived.py` が
   両層を読み込んで**新しい第三のファイル**を作る。どちらの原本も変更しない。
5. **匿名化・欠損を隠さない。** 九州の様式5は設備名が一部匿名（`□□□□線１Ｌ`）。
   `anonymized` 列で機械的に印を付け、名前照合の母数から除く。
   母数を黙って減らすと recall が実態より良く見える。

---

## 3. なぜこの分離が必要か（この規約が防ぐ事故）

- **循環参照**: derived の空容量を observed 扱いで再取り込みすると、
  「自分の計算で自分の計算を検証した」トートロジーになる。
  過去に論文で検証隠蔽が問題になった経緯がある（[[project_agj_integrity_review]]）。
- **誤差の消滅**: 混ざると「モデルと実績が一致した」ように見えるが、
  それは同じ数字を2回書いただけになる。
- **出典の断絶**: observed には出典があり derived には無い。混ぜると出典が付かない行が
  出典付きの顔をする。「嘘をつかない」原則（[[project_agj_capacity_provenance]]）に反する。

## 4. 現状（2026-08-11 実測）

**observed 側で新規取得したもの** — 様式5 インピーダンス、7社18ファイル:

| 事業者 | 形式 | 状態 |
|---|---|---|
| 北海道 / 北陸 / 中国 / 四国 / 九州 | xlsx | 取得済（列レイアウト5社一致・全社1000MVAベース） |
| 東京 / 関西 | PDF | 取得済（表抽出は未実装） |
| 東北 / 中部 / 沖縄 | — | **未発見**。制度上は存在するはずで、公表ページの別階層を要探索 |

**制度的根拠**: 資源エネルギー庁「系統情報の公表の考え方」（平成24年12月制定・令和3年5月改定）が
様式を定めて全一般送配電事業者に公表を求めている。
→ 1社で見つかった様式は他社にも存在する、という探索方針が成り立つ。

**derived 側の対応物**: `docs/data/powerflow/`（AC/DC潮流）、`docs/data/n1/`（N-1）、
Ybus は現状 OSM幾何＋線種推定による derived。
→ observed のインピーダンスが入手できた区間については、
   **derived の推定値を observed で検証できる**ようになった（これまで正解が無かった）。
