## 1. 核となる型 — 是正エピソードの5要素

各是正(介入)を同じ構造で記録することが手法化の本体。論文の「診断→処置→評価」に対応:

| 要素 | 内容 | 例(介入#31) |
|---|---|---|
| ①現象 | 何が観測されたか(発見の契機) | オーナー指摘「四国関西の直線が長すぎる」 |
| ②根本原因 | なぜ悪かったか(診断手順つき) | kv=0タイが両端max(500kV)を継承し低Z並列交流枝に。DCがACループ形成 |
| ③是正 | 介入の内容+帳簿+可逆化(無効化手段) | in_service=False(--synthetic-ties-liveで復元可) |
| ④改善の定量 | A/Bで何が良くなったか | 観測整合は不変・二重計上解消・関門−216→+383MWの転流実測 |
| ⑤限界 | 100%でない部分を明示 | 東北東京は340m未縫合で通電維持。DCのMW注入は未モデル化 |

⑤が本手法の肝: 「滑らかさは検証の証拠ではない」の実践として、**適用できなかった範囲・
残差を必ず数える**(EGGCの「直線維持243本」、L_DBの「未突合37地点」のように)。

## 2. ページ設計(実装時)

- **正本**: `docs/reports/improvements_catalog.yaml` — 各エピソードを5要素+図パス+
  介入台帳#N+レポートリンクで構造化(判断を含むため人手記述)
- **生成**: `scripts/build_improvements_page.py` が YAML→`docs/improvements.html` を生成し、
  regenerate_all の STEPS に組込(手書きHTMLはdriftする=pages正典忠実度監査の教訓)
- **表示**: エピソードごとに before/after 図を左右並置、5要素をカード表示、
  台帳#N・レポート・commit hashへの相互リンク。時系列と「層別」(幾何/トポロジ/電気/データ)の
  2軸で並べ替え可能に
- **index.htmlの陳腐化対策**: 散文の数字はビルド時に summary.json 等から注入
  (検算スクリプト issue#40 の思想)。手書き数字を残さない

## 4. EGGC拡張構想(オーナー発意 2026-08-17): 候補補完

「EGGCについては、候補補完があれば今後手法として検討していきたい」— OSM未収載区間
(現在は誠実に直線維持している45本+新規判読接続)に対し、**実線形の候補を生成して
人間承認で採用**する枠組み。証拠ゲートの精神は不変(自動採用しない):

- 候補源の案: ①OSMの孤立鉄塔(power=tower)点列の連なり ②地理院空中写真・基盤地図の
  送電線記号 ③地形コスト最小経路(河川・尾根・道路沿いの事前分布) ④他事業者図の
  ジオリファレンス(open-keitouzuの手法応用)
- 出力: 候補線形+確度スコア+根拠を帳簿化 → オーナー承認で採用(overrides方式)
- 位置づけ: EGGC(証拠ゲート付き系統コンフレーション)の第2段「証拠が薄い区間の
  候補提示層」。手法名の候補は実装時に再検討
