## 何が判定できるか

1. **AC方程式**：NR、50反復、1e-4 MVA。全稼働母線の有限電圧、需要保持、最終不整合も確認。
2. **発電機Q上下限**：収束フラグとは別に、結果と各発電機の上下限を再照合。
3. **運転範囲**：0.9–1.1 pu、線路・変圧器100%をスクリーニング。これは本ツールの仮の評価範囲であり、各設備の正式な運用基準ではない。
4. **Ybus**：島ごとの基準母線を除いた行列、対角スケーリング後、flat-startのAC Jacobianの疎行列1ノルム条件数推定。
5. **不収束の場所**：Q制約を適用する内側Newtonを追跡し、失敗時は注入量のホモトピーで最後の収束点まで戻る。その点のJacobianから `d|V|/dα` を出す。

**αはQ制約の切り替え時の人工的な注入量補間であり、需要倍率でも供給可能率でもない。**
この方法の停止はAC解が存在しない証明ではない。Ybusの条件数が大きいことも、単独では不収束や不正接続を意味しない。
孤立した基準母線のYbus対角ゼロを、直ちに異常としない。

## 今回のBefore/After

対象は東日本6,253母線、需要55,250 MWの推定運転点。220島・220基準母線のうち208は既存の仮想補給モデルに由来する。
全国同期系統の完全な実測再現や、島の物理的自立運転を検証したものではない。

- **支線復元**：OSMの宮城中央支線と構内引込2本を使い、青葉幹線の元の経路上に分岐点を追加。東北電力ネットワークの公開表でも500 kV・2回線・「青葉幹線分岐→宮城中央変電所」を照合。元の経路を切り捨てずに分割し、合計距離とR/X/Cを保持する。追加線の定数は既存500 kV既定値で、実測ではない。
- **分割だけの対照試験**：DCの元線路潮流差は約1.36e-9 MW。ACではπ型線路の充電容量の置き場所が変わるため、完全同値とはしない。
- **需要重み補正**：同じOSM設備・地域・電圧の70組について、合成需要の配分重みを一設備分にする。地域P/Q合計を保って再配分し、既存の推定80%補償シャントも同じ比率で更新。全設備点・線路・発電機を残す。これは推定需要の事前分布の修正であり、実測需要の重複を確認したという意味ではない。

元モデルと2つの修正案とも、目標需要でのQ制約付きACは未収束。Q制約を外した診断では、大郷の問題線路が約1,007%→198%、最低電圧が0.834→0.935 puへ改善。
ただしQ制約違反は残り、全体の条件数推定も単調には改善しない。
修正後の需要・発電・推定補償を80%にした点ではAC方程式とQ制約が通るが、最低電圧0.686 pu・過負荷が残る。
**目標需要でのAC合格、実際の系統精度向上率、運用可能性を宣言しない。**

## Claudeの確認箇所

- 宮城中央支線の欠落がどのbuild段階で起きたか。元way IDとポリラインを保った枝分岐を本番ビルダーに移植できるか。
- 同一設備の配分重みと母線の同一性を分離する。多電圧・母線区分を統合せず、観測需要はこの補正の対象外にする。
- 伊豆66 kV側の供給端、回線数、地点需要を一次資料で照合する。推定負荷率が高い線を理由なく削除したり、Q容量を無制限にしない。
- `results.json` の62件の線路両端電圧不一致を確認する。異電圧の直結か、母線階級・設備定義の誤りかを個別に判定する。
- 発電機の接続先・運転P/Q・AVR能力、補償設備、仮想補給を検証する。小容量発電機をPV母線にした影響を定量化する。

## 実装上の注意

`src/powerflow/ac_validation.py` のQ追跡はpandapower内部関数を一時的に置き換えるため、**専用の単一プロセス**で実行する。例外時も `finally` で復元する。
公開再実行CLIは並列スレッドでsolverを呼ばない。未知の版で黙って動かさず、バージョン不一致を拒否する。
古いYbusメモの「DCなら常に可解」「条件数だけでAC可解性を判定」といった一般化は、この判定には使用しない。

探索履歴は [exploration](reports/codex_ac_diagnosis_2026-09-15/exploration/) に保存。
初期探索の需要補正は68組、確定版再実行はsupplementも検証した70組であり、数値を混同しない。
人口傾斜、伊豆の仮2回線化、補償量変更、Q制約の再解放を含む実験solverなどは未収束で、修正案へ採用していない。
