# 変電所の構内結線(node-breaker 観測層)

2026-10-07 追加。変電所の中の母線・ベイ・開閉器・変圧器の巻線・線路の端を、**OSM の node ID の共有だけ**で結んだ台帳。
方法は All-AU-Grid がまとめ、All-EU-Grid が欧州全体で検証して規則を足したもの(移植元は All-EU-Grid commit 5d85ba9)。それを日本に移し、日本の OSM で見つかった穴を 2 つ埋めた。
採用の経緯と数字は [reports/station_node_breaker_adoption_2026-10-07.md](reports/station_node_breaker_adoption_2026-10-07.md)。

## 変電所を表す 2 つの層

このプロジェクトには変電所の中を表すものが 2 つある。役割が違うので、統合しない。

| | 観測層(この文書) | SubSLD の構造 DB([SUBSLD_METHOD.md](SUBSLD_METHOD.md)) |
|---|---|---|
| 置き場所 | `data/stations/`(`scripts/build_station_db.py`) | `data/structures/`(`scripts/build_structures_batch.py`) |
| 入力 | Geofabrik の日本 PBF を電力だけに絞ったもの(node ID つき) | 地域別 Overpass の GeoJSON(node ID なし) |
| 結線の根拠 | OSM の node ID の共有 | 座標を小数 6 桁に丸めた頂点の共有 |
| 開閉器 | OSM の実物。状態は不明のまま | ベイから推した開閉点(母線連絡は常時開を既定) |
| 変圧器 | OSM の実機。巻線ごとに端子 | 電圧階級の「梯子」(隣どうしを結ぶ仮説) |
| 線路の端 | 敷地内・柵外 25 m・はみ出したベイの先まで | 頂点共有 > 敷地内 > 引込帯 0.6 km |
| 使い道 | 観測の台帳。仮説の点検(梯子・母線の分かれ) | 単線結線図(Pages の SubSLD)・Ybus の銘板の当て先・CIM 書き出し |

**観測層は「何が描かれているか」、構造 DB は「計算に使う仮説」**。観測で仮説を点検し、食い違いは一覧にして人が判断する
(`scripts/compare_station_layers.py`)。仮説を観測で自動的に置き換えることはしない([MODEL_INTERVENTIONS.md](MODEL_INTERVENTIONS.md) の手順による)。

## 規則

全体は All-AU-Grid の `docs/SUBSTATION_METHOD.md`(v1.1)。要点は次の通り。

- 2 本の導体がつながるのは、OSM の node を共有するときだけ。地図上で交差・近接しても結ばない。
- 開閉器は入ってくる腕ごとに端子を分ける。way の途中にあっても、そこで導体を切る。
- 変圧器は 1 台を 1 機器とし、電圧側ごとに巻線と端子を持つ。三巻線を 3 台にしない。巻線どうしを導線で結ばない。
- 変電所に 500/275/154 kV があるだけでは変圧器を作らない。
- 分からないものは分からないまま課題(`issues`)に残す。電圧 0・台数 1・常時閉で埋めない。
- 敷地への帰属は多角形で決める: 包含(`covered`)、入れ子なら最内側(`innermost_nested`)、柵外 25 m(`buffer`)。部分重複は未確定。

All-EU-Grid が欧州で足した規則(どれも根拠のラベル付き):

| 規則 | ラベル |
|---|---|
| 母線の分岐点の断路器は、母線を切らずに母線とベイの間に入れる | 端子の method `busbar_junction` |
| 接地開閉器は導体を切らず、1 端子 | `switch=earthing` |
| 柵のすぐ外の門型鉄構・機器を、多角形 1 つの 25 m 以内なら帰属させる | membership `buffer` |
| `voltage=275000;77000` だけの変圧器に、値ごとの巻線を作る(役割は不明) | voltage_method `device_voltage_list` |
| 敷地から一度も出ない power=line は構内配線 | conductor_rule `inside_one_footprint` |
| 全閉仮定では、両側の決まらない開閉器でも腕どうしを結ぶ(腕が全部 1 つの既知の階級にあるときだけ。接地開閉器は結ばない) | `views.analyse` の `switch_arm` |
| 全閉でもつながらない階級について、部分どうしの最短距離を出す | `views.gaps`(`summary.json` の `split_level_gap_m`) |

## 移植元との差分(日本で変えたこと)

コアは共通ライブラリにせず、各リポジトリが写しを持つ(オーナー判断 2026-10-07)。そのぶん、規則が黙って分かれないよう差分はここにすべて書き、
規則の追加は姉妹プロジェクトとパッチで渡し合う。移植元のファイルと SHA-256 は `src/stations/__init__.py`。

| 差分 | 理由 | 実装 |
|---|---|---|
| **50 Hz と 60 Hz を同じ系統 `ac`** にする(欧州版は 50 Hz 以外を `ac_other` として別階級) | 西日本の線には `frequency=60` が付き、同じ変電所の無タグの母線と同じ階級に入るべき。欧州版のままだとタグの有無で 1 つの階級が 2 つに割れる | `src/stations/tags.py` `classify_freq` |
| 50 Hz と 60 Hz のタグの導体が同じ階級にある所を別に拾う | 周波数変換所(新信濃・佐久間など)の候補と、タグの誤り | `summary.json` の `frequency_mixed_levels`(8 階級) |
| **柵の外へはみ出して描かれたベイ・母線**を、100 m まで敷地に含める(`internal_extension`) | 日本の OSM では `line=bay` を柵の外の門型鉄構・鉄塔まで描くことが多い。移植元のままだと構内配線 987 本が敷地を決められず、そこから出る線路が変電所につながらなかった。1 つの敷地からはみ出す 901 本の中央値は 47 m で、89% が 100 m 以内 | `src/stations/core.py` `model(..., extension_m=)`。既定 0(移植元と同じ)、日本の生成では 100 |
| 事業者名から鉄道系統を推す規則を外した | DB Energie などの欧州の事業者名の規則 | `src/stations/tags.py` |
| 構造 DB との対応を OSM の (type, id) で取る | 移植元の比較は重心と名前で照合していた | `scripts/build_station_db.py` `structure_crosswalk` |

`internal_extension` は All-EU-Grid 5d85ba9 で移植元にも入った(`model()` の既定 0、EU の DB は 100 m)。コード上の差分は 50/60 Hz だけになった。
同じ 5d85ba9 で、EU は独立のレビューを受けて `tee_junction`(通り抜ける線から分岐する線の断路器)を撤回した。
AU の実入力で 9 台中 1 台しか妥当でなく、way の切り方を物理の根拠にしていたため。日本の数字はこれを反映済み。

`internal_extension` の効果(2026-10-06 の日本の抽出、0 m → 100 m):

| | 0 m(移植元) | 100 m |
|---|---:|---:|
| 敷地を決められない構内配線(`internal_way_without_unique_site`) | 987 | 177 |
| ベイ | 6,713 | 7,500 |
| 線路の端が構内の配線に載る(`wired`) | 5,695 | 5,983 |
| 全閉仮定で母線に届く線路の端 | 2,718 | 2,837 |
| 両側の決まらない開閉器(`switch_ports_unresolved`) | 311 | 254 |

## SubSLD の構造 DB との突き合わせ

`scripts/compare_station_layers.py` → `docs/reports/station_layers_<日付>/`(`summary.json`、`transformer_pair_review.csv`)。

**変圧器の電圧の組**(OSM が両側の巻線電圧付きで変圧器を描く 518 敷地、地域境界の重複は 1 つに数える):

| 判定 | 敷地 | 割合 |
|---|---:|---:|
| 梯子と同じ | 365 | 70% |
| OSM が梯子の一部しか描いていない | 55 | 11% |
| 構造 DB に無い階級(6 kV など)への実機 | 66 | 13% |
| **梯子が段を飛ばす実機**(275/77 の直結など) | 32 | 6% |

梯子の仮定は構造 DB だけでなく潮流モデル(`run_full_powerflow_from_db.py` の変電所内の変圧器)にもある。
**介入 #49** で、各社の公表一覧の組がある変電所はそれを最優先にする(公表 > 観測 > 梯子。全国の台帳での採点は
[reports/transformer_topology_2026-10-08.md](reports/transformer_topology_2026-10-08.md))。
**介入 #48**(`src/model/site_transformers.py`)で、観測した組を先に張り、残る階級だけ梯子でつなぐ。構造 DB・潮流とも既定 ON
(潮流は 10-08 に [INTERVENTION_VALIDATION.md](INTERVENTION_VALIDATION.md) の 3 つの物差しで検証してから。直結の組は 21 変電所中 20 が
各社の公表一覧に実在)。数字は [MODEL_INTERVENTIONS.md](MODEL_INTERVENTIONS.md) の #48 と採用記録の §10・§11。

## 限界

- OSM に開閉状態・定格・インピーダンスは無い。全閉は仮説で、状態として書かない。
- 日本の OSM は構内の描き込みが薄い。構内の記録がある敷地の 55% は線路の端だけ。
- `internal_extension` は、柵の外の門型鉄構が 100 m 以内という日本の描き方の分布に合わせた値。100 m を超える 78 本は帰属させていない。
- 構造 DB(Overpass、2026-08)と観測層(Geofabrik、2026-10-06)は観測の時点が違う。突き合わせは敷地ごとの比較で、同じデータとは言わない。
- CGMES の node-breaker 交換(EQ の母線区間・開閉器)はまだ出していない。CIM 書き出しは bus-branch(`src/cim`)。
