# Pages（io）の棚卸し — 残す・統合する・導線から外す

GitHub Pages（https://lutelute.github.io/All-Japan-Grid/）を一新するための台帳。2026-10-20 にオーナーの指示（「io 一新したい」「棚卸しし始めて、統合するところ、捨てるところ。洗練していく」）を受けて作った。

- **原則（オーナー指示 10-20「資産はちゃんと崩さずに残しておくこと」）**：ページ・データ・レポートは**消さない・場所を変えない・中身を書き換えない**。一新で変えるのは、公開の導線（トップ・ナビゲーション・地図のタブ）と、新しく作る共通部品だけ。古い URL はそのまま開ける。
- **判定**：残す / 作り直す / 統合する / **アーカイブ**（導線から外し、「アーカイブ」一覧から開けるようにする。ファイルとデータはそのまま置き、更新はしない）。
  - 以前の「捨てる」はすべて「アーカイブ」と読み替える。消すものは無い。
- **状態**：「案」はこの台帳の提案、「決定」はオーナーが決めたもの。決まったら「決定」に書き換える。
- 事実（サイズ・最終更新・参照）は 2026-10-20 の main で機械的に集めた。動作は Playwright で実際にホバー・クリックして確かめた（公開サイトと、手元で配信した docs/ の両方）。

## 3. 直すべき不具合（確認済み）

1. **map.html の送電線と変電所のホバーとクリックが効かない**（2026-04-02 の `3e014ab7` から）。
   - `docs/js/grid_map.js:201` の `preferCanvas: true` と、`:255-256` の変電所用・発電所用の専用層のせいで、地図全面に canvas が 3 枚重なる。
   - 一番上の発電所の canvas がイベントを全部取り、下の線と変電所に届かない。Leaflet の canvas は下の層にイベントを渡さない。
   - 発電所の層を OFF にしても、空の canvas が残って塞ぐ。潮流解析タブの線も同じ理由で効かない。
2. **直リンク（`map.html#tab-ybus`・`#tab-sld`）で中身が起動しない**（09-21 の `07be84a4` から）。`openTabFromHash()` が、sld.js と ybus_sim.js がタブにクリック処理を付けるより先に走る。
3. **線が当たりにくい**。canvas の当たり判定の余白が 0 で、線の太さは 1.5〜3 px しかない。
4. **今のテストではこの種の不具合を見つけられない**。`tests/test_flow_map_integrity.py` は構文検査（`node --check`）だけ。

## 4. 作り直しの骨格（案）

```
トップ（index）── 共通ヘッダ・ナビゲーション
├─ 地図 ……… 系統図 / エリア / 潮流（現在・日別・UC）を「表示」で切り替え（map と flow_map を統合）
├─ 変電所 …… SubSLD
├─ 解析 ……… Ybus シミュレータ・N-1（今の正典で作り直す）
├─ 編集 ……… editor（＋ review を続けるならここ）
├─ ダウンロード
├─ 学ぶ ……… EGGC の教材・スライド
└─ レポート … codex_*・station_changes（記録。更新しない）
```

共通部品（`docs/js/` に置く）：

- **地図部品**：描画面は canvas 1 枚で、当たり判定の余白を付ける。重なり順は追加の順で決める。背景地図を切り替えられる。
- **ホバーとクリックの扱い**：部品がその点の一番上の対象を調べ、説明の吹き出し・詳しい説明・横のパネルを出す。各層は「説明の中身を作る関数」だけを渡す。
- **タブと直リンク**：各表示が「開くときの処理」を登録し、すべての登録が済んでから URL の `#` を読む。
- **凡例・共通ヘッダ**
- **データの持ち方**：地図に出すものは built（正典）の 1 系統から書き出し、版の番号を入れる。全ページが同じ版を読む。
- **検査**：Playwright で地図を開き、線・変電所・発電所の上で、一番上の要素が地図の描画面であることと、実際に説明が出ることを確かめる（CI）。

## 6. 進め方

1. 共通の地図部品を作り、まず map.html の系統図とエリアを載せ替えて §3 の 1〜3 を直す。Playwright の検査を足す（2026-10-20 着手）。
2. この台帳の判定が「決定」になったものから、導線から外す・アーカイブ一覧に載せる・統合する（ファイルは消さない）。
3. flow_map を同じ部品に載せ、地図ページとして統合する。
4. 解析ページを作る。データは今の正典で作り直す。
