# 問題・境界状態・解の品質の契約案

状態: 設計仕様。既存コードの実装済み機能を表すものではない。

## 1. 最初に固定する問題

**UC800-Z-v1:** 個別に起動停止する最大800台の発電機、1h刻み、決定論的、ゾーン間transport network、外生の定検、再エネ利用可能量、揚水・蓄電。800台は対象ユニット台帳の実数で確認し、非制御電源・storage・集約施設の数を別記する。800台の観測データが揃わなければ実数ケースと合成800台ケースを分ける。

対象期間はタイムスタンプ配列で定義する。JST、欠測処理、年度/暦年、8760/8784h、年頭前史、年末条件をmanifestに保存する。365日を機械的に当てはめない。発電所からユニットへの分割は出典または合成仮定を残す。

目的は以下の費用和の最小化。

\[
 C=\sum_{g,t}\{\Delta t\,[C^{fuel}_{gt}(p_{gt})+c^{nl}_g u_{gt}]
   +C^{start}_{gt}(v_{gt},h_{gt})+c^{stop}_g w_{gt}\}
   +C^{storage}+C^{curtailment}+C^{other}.
\]

通貨・基準年・燃料費単位を統一する。fuelはまず線形または凸区分線形。起動費はイベント費なのでΔtを掛けない。全ソルバーで同じ目的関数を使い、表示用の経済費用と最適化目的値を別フィールドで保存する。

必要な制約:

- `u_t - u_(t-1) = v_t - w_t`、起動停止の排他、最小運転/停止時間、出力上下限、通常・起動・停止時のランプ。
- hot/warm/coldの費用・閾値、年頭の停止前史。起動軌道をモデル化する場合は進行中の起動段階も状態に含める。
- ゾーン需給、方向別・時変連系線容量、50/60Hz間の連系制約。沖縄等の独立系統を正しく区別する。
- 予備力の変数、ヘッドルーム、応動時間内ランプ、蓄電の持続時間。送達可能性を未モデル化なら地域予備力の保証範囲を限定する。
- SOC遷移、充放電効率、電力・エネルギー上下限、充放電の排他、境界SOC。自然流入のある貯水池と純揚水を区別する。
- 外生の停止・定検。燃料・水・CO2の長期予算は、根拠のあるデータを揃えた拡張ケースで追加し、基礎ケースに暗黙に混ぜない。

負荷遮断や線路超過の緩和を設ける診断モデルは別の問題IDにする。厳格な供給充足ケースでは許さない。ペナルティ付きモデルの最適解でも未供給があれば運用要件を満たしたとは表示しない。再エネ抑制は利用可能量との差として明示し、一般的なspillが何を捨てているのかを曖昧にしない。

## 2. 系統モデルの段階

| 水準 | 内容 | 保証範囲 |
|---|---|---|
| Z | ゾーン需給＋連系線容量 | ゾーンモデルのMILP実行可能性・最適性 |
| D | 母線DC、PTDF/角度、線路容量 | 指定DCモデルの実行可能性・最適性 |
| S | D＋指定事故集合のN-1 | 指定事故集合についてのDCセキュリティ |
| A-check | 解をAC潮流・必要なら再給電で検証 | 検証した時刻・事故・運転点のAC実行可能性。AC大域最適性ではない |

系統データを消費する前に[既存のYbusゲート](../../UC_HANDOFF.md)を実行し、入力ハッシュと結果を記録する。Ybusの良条件性、電圧・熱容量の運用適合性、UC最適性は別の検証軸である。

制約の逐次追加は、候補解を全対象線路・全対象事故で最後に検査してから認定する。PTDF/LODFの閾値省略、事故スクリーニングによる除外は正当性の条件を明記する。島を生む事故では通常のLODF式が使えると仮定しない。

## 3. 境界状態

時刻kの直後から次の区間に渡す状態を、少なくとも次の組とする。

\[
 s_k=(u_k,p_k,\tau^{on/off}_k,\text{startup phase}_k,
       SOC_k,V^{water}_k,B^{fuel}_k,B^{CO2}_k).
\]

採用していない資源・起動軌道は省略可能。温度を別の状態方程式でモデル化する場合は、その状態も加える。単なる24/48h重複では状態一致の代わりにならない。

- 最小up/downとhot/warm/coldの判定に必要な前史を保持する。履歴を上限で切る場合、全制約・全費用が変わらないことを確認する。
- **前区間の確定末尾p**から次区間の最初のpへのランプを制約に含める。
- 独立チャンクの解は候補。共有境界を固定・調整した再求解後、全期間を検証して初めてUBとして採用する。
- 局所再最適化では左右両方の状態・残余資源を整合させる。左右を固定すると修復不能なら修復窓を広げる。
- 年間UBは各実施時刻の費用を一度だけ集計する。lookaheadの費用・warmupの費用は重複加算しない。

年末は (a) 固定/範囲指定の終端状態、(b) 年周期、(c) 残存価値を持つ開放端、のいずれかを問題定義で固定する。第1版は明示的な終端SOC範囲と年末の残存up/down義務を採用候補とし、閾値をmanifestに置く。日ごとのSOCリセットで年間問題を置き換えない。先読み用の近似終端価値を使っても、最終UBは元の年間目的で評価する。

## 4. 年間下界の構成

年間MILPを、週ブロックbの局所変数x_bと結合制約に分ける。

\[
 z^*=\min\sum_b c_b^T x_b,\quad
 x_b\in X_b,\quad \sum_b A_bx_b=d,\quad \sum_b G_bx_b\le h.
\]

X_bには週内の整数制約・物理制約、Aには境界状態の複製一致、Gには年間資源等を置く。跨境界の最小up/downや起動費履歴も、十分な状態表現・境界変数・結合制約へ正しく写す。制約を落とす緩和と、元問題と等価な分割モデルを区別する。二重計上しない費用の分配が必要である。

等式乗数λは自由、`≤`制約の乗数μは非負とすると、

\[
 q(\lambda,\mu)=\sum_b\min_{x_b\in X_b}
 (c_b+A_b^T\lambda+G_b^T\mu)^Tx_b-\lambda^Td-\mu^Th
 \le z^*.
\]

時間制限付き部分MIPでは、各最小値の代わりに**部分ソルバーの有効なdual bound** `l_b` を使える。そのときも `sum(l_b)-λᵀd-μᵀh ≤ z*`。部分問題のincumbentは最小値の上側なので、同じ用途には使えない。

複製した境界状態にも物理的な上下限を付ける。部分問題が非有界ならその評価のLBは−∞となり、有限の品質保証としては使えない。元問題と対応しない余分な固定条件を加えて、見かけの下界を押し上げない。

最初はλ=μ=0でもよい。有限LBを確認後、安定化した乗数更新を導入する。未最適の部分解から得た残差は厳密なsubgradientとは限らないため、乗数更新は改善ヒューリスティックとして扱い、各LBの有効性は独立に保つ。精度制御付きの更新法を別途比較する。

異なる乗数で計算したブロックLBを、そのまま一つの和に混ぜない。非同期計算では `multiplier_id` とモデル版を持ち、全ブロックが揃った同一乗数の評価を認定する。再利用する場合は妥当な補正を導出する。認定済みの年間LBの最大値を保持する。

この分解の重要な初期試験は、小ケースで **各乗数のLB ≤ 一括MILP最適値 ≤ 検証済みUB** が成り立つこと。境界SOCやuを経験的な値に固定した部分問題は元問題の制限になりうるので、その目的値の合計を下界にしない。

## 5. 列生成・Bendersを採用する条件

- GCG/列生成: 発電機または週の実行可能軌道を列とする候補。制限された列だけのmaster LPの値は、元の全列LPに対して上側になりうる。pricingが完了したこと、またはreduced-cost boundによる有効な補正があることを確認してLBを認定する。整数解の証明には分枝等が別途必要。
- Benders: masterに固定すべき整数決定を全て置き、残りがLPとなる構成ならdual cutを使える。週UCの整数価値関数をそのまま凸LPの価値関数として扱わない。logic-based / integer L-shaped等は仮定・収束条件を確認した別候補とする。
- LPの固定commitmentから得る限界価格は、その固定状態に対する価格。年間MILPの下界や整数性込みの市場価格と混同しない。

## 6. 独立検証と結果形式

検証器はモデル構築関数を再利用して同じ誤りを追認せず、正準入力と保存解から別途制約・費用を評価する。最小ケースは列挙・一括MILPとも照合する。

検証対象は整数性、需給、出力、ランプ、最小時間、起動種別、予備力、定検、連系線、SOC、水・燃料・CO2、年頭・年末・全窓境界、費用。数値許容差は単位別の絶対値＋相対値で定め、規模と係数スケーリングの試験後に固定する。最大残差と発生位置を保存し、隠れた丸め修正で合格させない。

最低限のrun record:

| 区分 | フィールド |
|---|---|
| 同一性 | `instance_id`, `input_sha256`, `model_id`, `objective_id`, `boundary_policy_id`, git SHA |
| solver | 要求/実際のbackend、SCIP/UG/LP solver版、build flags、parameters、seed、MPI/threads |
| 状態 | `termination_reason`, `has_incumbent`, `feasibility_verified`, `bound_scope`, `gap_target_met` |
| 品質 | `solver_objective`, `economic_cost`, `primal_bound`, `dual_bound`, `gap_abs`, `gap_rel`, `solver_native_gap`, 残差 |
| 時間・資源 | 入出力/構築/presolve/root/探索/検証/総時間、node数、peak RSS、実測CPU時間、割当core-hour |
| 年間分解 | 各blockの範囲・状態・乗数ID・LB・費用所有範囲、年全体の検証、LBの導出ID |

共通の報告gapは、同じ目的関数・同じ問題範囲について `gap_abs=UB-LB`、`gap_rel=(UB-LB)/max(1 currency_unit, abs(UB))` と定義し、solver固有のgapとは別に保存する。非有限のboundや未検証のUBならgapはnull。許容差を超えてLB>UBなら不整合として停止し、0へ丸めない。

数値MILPの上下界による保証と、有理数による形式的証明は区別する。本計画の初期目標は、保存ログ・入力・モデル・許容差のもとで再現できる数値的な品質保証である。
