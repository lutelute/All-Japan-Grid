# 実系統の制約付き起動停止計画（SCUC）の設計

2026-10-25。オーナーの方針：「リアル系統での制約は他の人にはできない。これまでにできなかったことをできるようにする」。

## 何をできるようにするか

日本全国の **実在の送電網**（All-Japan-Grid の正典、154kV 以上の基幹網）で、

1. 線路の熱容量（平常時）と N-1（1 回線が切れても過負荷にならない）を入れた起動停止計画を、
2. 公開ソルバー（HiGHS、将来 SCIP/UG）で、
3. 上界と下界つきで解き、
4. 出てきた計画を交流潮流で検算する。

さらに「安いがこの線が切れたら危ない計画」と「少し高いが安全な計画」を、費用の差（安全のための費用）とあわせて地図の上で比べられるようにする。公開されている日本の研究は 10 地域の輸送モデルか小さな試験系統までで、全国の実系統の線路で SCUC を解いて検証した例は見当たらない（REFERENCES.md で確認を続ける）。

## 定式化

島 I（北海道・東（50 Hz）・西（60 Hz）・沖縄）ごとに、母線 b、監視する線 ℓ（154kV 以上の実在線と銘板つき変圧器）、時刻 t。

- 母線の注入：`inj[b,t] = Σ_{g∈b} p[g,t] + Σ_{s∈b}(dis − ch)[s,t] + Σ_{直流端子 k∈b} h[k,t] − d[b,t]`
- 平常時の流れ：`F[ℓ,t] = Σ_b PTDF[ℓ,b] · inj[b,t]`、`|F[ℓ,t]| ≤ cap_ℓ`
- N-1（線 k が切れたとき）：`|F[ℓ,t] + LODF[ℓ,k] · F[k,t]| ≤ cap_ℓ^緊急`（橋になる線の開放は「島が分かれる」として別に数える）
- 島の中の交流の地域間連系（東北–東京、中部–関西–中国–九州 など）は自由な流れの変数をやめ、物理（PTDF）で決まる流れにする。OCCTO の運用容量は、境界をまたぐ線の流れの和（flowgate）の上限として残す
- 直流（北海道–本州、東京–中部の FC、関西–四国の阿南紀北、中部–北陸の BTB）は今の UC どおり制御できる流れ `h[k,t]` とし、両端の母線に注入する
- 費用・最小運転停止・起動種別・蓄電は今の UC のまま（`src/uc`）

**行の数を抑える工夫**：監視する線は数千本 × 24 時間 × N-1 の組で、全部入れると数億行。そこで

1. 違反した（線, 時刻）だけを足して解き直す遅延制約生成（平常時 → N-1 の順）。各行の非零は島の発電機の数（数百）
2. 足す前に、PTDF の値が小さい母線を落とす（|PTDF| < 1e-3）
3. 解き直しは前の解を MIP start にする（`warm_start_schedules`、受け入れは確認済み）

**解けない線は「網のデータの問題」として出す**：今の正典と定格では、基本の断面でも過負荷が出る（過去の報告で合成定格のままだと東 1003%・西 433%）。そこで制約は柔らかくし（超過 1 MW あたり高い罰金）、罰金を払った線を一覧にする。SCUC がそのまま網のデータの検証器になる（どの線の定格・接続を疑うべきか）。

## 上界・下界

- 上界：検証器（今の `validate_uc_solution` に網の検査を足したもの）を通った計画の費用
- 下界：遅延制約生成の各回の MILP の下界は、制約を一部しか入れていない問題の下界なので、**全制約の問題の下界としても正しい**（制約を足すと最適値は上がるだけ）。最後の回で違反が 0 なら、その計画の費用と下界の幅がそのまま全体の幅になる

## 段階

| 段 | 中身 | 合格の条件 |
|---|---|---|
| 0 | 網の書き出し：島ごとの 154kV+ 網、定格（較正あり／なしの 2 通り）、PTDF/LODF、UC の機 → 母線（1 対 1）、地域需要 → 母線の配分。`scripts/scuc_network_export.py` → gpu3060 か pws-160core で実行 | 1 断面の DC 潮流が既存の N-1 スクリーニングと一致。機の対応の取りこぼし一覧 |
| 1 | 評価：今の UC の計画（地域モデル）を網に流し、平常時と N-1 の過負荷を時刻ごとに数える（リスク評価 v2） | 「安い計画はこの線が何時間あふれる」が地図に出る |
| 2 | 平常時の線の制約を入れた UC（遅延制約生成）、全国 24 時間 | 違反 0 で収束、幅つき。費用の上がり幅 = 網の制約の値段 |
| 3 | N-1 を入れる（LODF、遅延） | 違反 0。安全の値段 |
| 4 | 交流潮流で検算（pandapower、`nr_guard`） | 電圧・無効電力を含めて破綻しないか |
| 5 | 1 週間・年間（ローリング・段階的に分ける）、SCIP/UG での並列 | — |

## 守ること

- 線路別の定格の生値（関西・TEPCO など）は公開しない（`reference_utility_data_licensing`）。地図に出すのは負荷率と、公開できる出典の線だけ
- 盲信につながる修正（接続・値・配分）は `docs/MODEL_INTERVENTIONS.md` に登録してから使う
- 重い計算はこの Mac で回さない（gpu3060 / pws-160core）
