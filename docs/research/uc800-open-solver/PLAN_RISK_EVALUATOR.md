# 計画のリスク評価器（設計案、2026-10-25）

## なぜ要るか

UC は費用を最小にする計画を返すだけで、その計画が系統の上で危ないかどうかは見ていない。今の UC の系統は 10 地域の輸送モデル（連系線の容量だけ）で、送電損失・地域内の混雑・N-1・地域ごとの予備力を持たない。そこで、できた計画を All-Japan-Grid の正典の網に載せて外から確かめ、「安いが危ない計画」を見分ける。オーナーの発意（10-25）。

評価の対象は実機の UC（`config/uc_scenarios/fy2023r2` など、発電所単位の約 520 記録）。合成 800 台は網の上の位置を持たないので、評価器の対象ではない。

## 物差し（計画 1 本ごとに出す）

| 物差し | 中身 | 使う部品 |
|---|---|---|
| 損失 | 時間ごとの AC 潮流の送電損失（MW、MWh） | `scripts/uc_to_pf_built.py`（`loss_mw`） |
| 混雑 | 物理クラスの線路・変圧器の負荷率、過負荷の時間数と MW | `--dump-line-flows`、`sensitivity/n1_screening.py` の `classify()` |
| N-1 | 1 本切れたときの過負荷の件数と MW、孤立する負荷、橋（切れると分断する枝） | `src/powerflow/contingency.py` の `screen()`（LODF、1 断面約 3 秒） |
| 予備力 | 地域ごとの上げ代・下げ代、最大単機の脱落に耐えるか、ランプの余裕 | `src/dynamics/agc.py` の `build_area_from_uc`・`largest_online_unit` |
| 補償の費用 | N-1 の過負荷を出力の組み替えで解くのに要る費用 | 新しく作る（例：pandapower の `rundcopp` に UC の燃料費を渡す） |
| 整合の目安 | 注入後の slack の大きさ、電圧の最小・最大、需要を満たした割合 | `uc_to_pf_built.py`（`slack_abs_mw`・`vm_min`・`served_frac`） |

出力は「費用とリスクの表」。最安の計画と、予備力を足した計画、連系線に余裕を持たせた計画などを同じ表に並べて比べる。

## 今の部品の限界（棚卸し、10-25）

- 発電機の対応は地域×燃料の容量比例。UC 側（`{region}_g{idx}`、`src/uc/scenario.py:393`）と潮流側（発電所名）は同じ `data/{region}_plants.geojson` から作るので 1 対 1 に結べるが、まだ結んでいない
- 定格の多くは合成。線路は電圧クラスごとの値（較正の係数 0.546 は既定で無効）、変圧器の銘板は東 134/680・西 158/999 だけ。そのままだと基本断面で負荷率が東 1003%・西 433% になるので、物理クラスに絞り、較正ありとなしの両方で数える
- 注入後の slack が大きい（西で時間あたり 6.7〜7.8 GW）。slack が大きい時間の数字は、その旨を添えて出す
- N-1 の道具は、メリットオーダーの 1 断面で作った網（`production_net`）を前提にしていて、UC の出力を受けない
- UC の結果をファイルから読み戻す口がない（`result_exporter.py` は書き出しだけ）。今はどのドライバも UC を解き直す
- 補償（再給電）の計算は無い

## 作る順

1. **v0（1 日・DC＋LODF）**：`uc_to_pf_built.py --islands hokkaido east west okinawa --all-hours --boundary-injection --dump-line-flows DIR` で 24 時間の AC 潮流と線路の流れを出し、物理クラスの過負荷を数える。注入した網の DC 解を f0(t) として、時間ごとに `contingency.screen()` で N-1 を数える。地域ごとの上げ代・下げ代を `build_area_from_uc` で出す
2. **v1**：UC の結果を JSON で保存・読み戻す口を足し、解き直しをやめる。UC 側と潮流側の発電機を発電所名で 1 対 1 に結ぶ
3. **v2**：N-1 の過負荷を解く再給電の費用（DC-OPF）を出し、「この計画の安さのうち、いくらがリスクの先送りか」を数字にする
4. **v3**：評価で見つかった危ない断面を、UC 側に戻す（その時間だけ PTDF の制約を足す、予備力を地域ごとに持たせる）。安さとリスクの組み合わせを比べる

## 数字の扱い

- 定格・slack・較正の有無で数字が大きく変わるので、どの設定で出した数字かを表に必ず書く
- 合成の定格で出た過負荷を「危ない」と言い切らない。物理クラスの実定格がある枝と、推定の枝を分けて数える
